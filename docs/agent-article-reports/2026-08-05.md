## Search Agent

### 1. Search, Inspect, Fetch: Exploiting Structure-Aware Boolean Retrieval for Deep-Research Agents

- 链接：https://arxiv.org/abs/2608.02751
- 方向：Search Agent / Deep Research / Structured Retrieval
- 评分：4.905
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：常见 deep-research agent 使用 Search-Visit 循环：先搜索，再打开整页，把网页全文塞进上下文。这种方式没有利用网页天然的标题、章节、metadata 等结构，导致 agent 明明只需要某个段落，却要消耗大量 token 读取整页，也更容易把无关内容带入后续推理。

**核心方法**：论文提出 SIEVE，即 search-inspect-fetch。agent 先生成 Boolean Query Language 表达式，在网页字段上做候选过滤；随后用可替换的 ranker 对候选排序；再展示包含标题、章节和 metadata 的结构化 result cards 供 agent inspect；最后只 fetch 被选中的章节，而不是整页。它把“什么网页可被考虑”和“哪个结果优先检查”分开：Boolean selection 决定 eligible set，BM25、dense 或 fusion ranker 决定排序。

**创新点**：这篇直接击中 Search Agent 的上下文浪费问题。它不是单纯换一个 retriever，而是把网页结构暴露为可操作接口，让 agent 能对字段和 section 施加约束。对训练 search agent 来说，这意味着轨迹不应只记录 query 和网页 URL，还应记录字段过滤、结构化检查、section 选择和证据提取。

**实验与 benchmark**：作者构造 HotpotQA、MuSiQue 和 BROWSECOMP-PLUS 的 flat/structured 成对版本，保证问题和文本相同，只改变网页结构是否可寻址。指标包括 HotpotQA/MuSiQue 的 exact match、BCP-S 的 judge verdict accuracy、以及每题 distinct token 消耗。SIEVE 在三个集合上都达到最高准确率，相比最强 Search-Visit 配置提升 1.6/3.1/0.7 个准确率点，同时少用 20.7-50.6% token；BQL candidate selection 对所有九组 ranker-collection 组合都有帮助。

**可迁移价值**：适合直接作为 deep research agent 的工具协议：搜索工具返回的不应只是 snippet，而应是可 inspect 的结构化索引；fetch 工具应支持 section-level evidence。训练数据也可以把 BQL、section path 和最终引用绑定起来。

**局限**：评估仍基于离线 QA 集合和构造的结构化页面；真实网页的结构质量、动态内容和反爬限制会带来额外噪声。

### 2. Training Documents Reranker with Search Rubrics for Deep Research Agent

- 链接：https://arxiv.org/abs/2608.03527
- 方向：Search Agent / Reranking / Rubric Reward
- 评分：4.830
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：deep research agent 的检索模块不能只找“单篇相关文档”。最终答案需要一组文档共同覆盖查询需求，并且要避免冗余、过时、低权威或互相矛盾的证据。传统 retriever/reranker 多数按单文档相关性训练，很难显式优化“这组文档是否足够回答问题”。

**核心方法**：论文提出 query-oriented search rubrics，并据此训练 RubricRanker。rubrics 是层级结构：集合层关注 relevance、conciseness、consistency，文档层关注 source authority、timeliness 等维度；再用强 LLM 把 meta rubrics 展开成 query-specific rubrics 和权重。训练分两阶段：先做 rubrics-guided SFT，让 reranker 学会按 rubrics 选择文档；再做 rubric-based reinforcement learning，用 rubric 满足度作为偏好/奖励信号继续优化。

**创新点**：它把检索监督从“文档与 query 相似”推进到“文档集合满足哪些搜索标准”。这非常适合 Search Agent 后训练：每次搜索轨迹可以不只标注答案正确与否，还标注证据是否覆盖关键子问题、是否权威、是否互补、是否过时。

**实验与 benchmark**：摘要和前 8 页显示，RubricRanker 在四个 deep research benchmark 上比最强 baseline 高 2.6 分，并能泛化到五个 RAG benchmark。论文强调 deep research benchmark 测的是长答案所需的证据集合质量，RAG benchmark 则测试更通用的检索增强问答能力。

**可迁移价值**：可以把 rubrics 作为 search-agent reward model 的中间语言：query decomposition 生成要求，retriever/reranker 输出候选集合，judge 按 rubrics 打分。它比单一 relevance label 更适合训练多跳检索和长文档证据选择。

**局限**：rubrics 由强 LLM 合成，质量和偏差会传给 reranker；我只读取了 PDF 前 8 页，具体四个 deep research benchmark 名称和完整消融表未在可读片段中全部确认。

### 3. Field Aware Agent Skill Retrieval

- 链接：https://arxiv.org/abs/2608.02880
- 方向：General Agent / Skill Retrieval / Lifelong Agent
- 评分：4.640
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：长期运行的 agent 会积累越来越多技能文件，例如 `SKILL.md` 中的名称、描述、触发条件、步骤和正文。现有 skill retrieval 常把整个技能拼成一段文本检索，忽略了不同字段在“何时用”和“怎么用”上的作用差异。技能库变大后，这种扁平拼接会让相近但错误的技能更容易混入。

**核心方法**：论文把每个 skill 保留为多字段对象，对每个字段分别计算 sparse 和 dense similarity，形成 field-aware 的张量化表示。之后用 uniform weights 或小型 MLP 融合字段级分数，得到最终检索排序。核心思想很直接：不要把技能说明压扁，先保留结构，再学习哪些字段对匹配任务最有用。

**创新点**：这篇与 Codex/agent skill 系统高度相关。它指出 skill retrieval 的关键不一定是更大的 embedding 模型，而是把 skill 文件中已经存在的结构用起来。对 agent post-training 来说，可以把“任务描述 -> 正确 skill -> 字段贡献”作为检索监督，让模型学会区分名字相近但适用条件不同的技能。

**实验与 benchmark**：论文在 SkillRet 和 SRA-Bench 两个 skill retrieval benchmark 上评估。field-aware MLP 达到 SkillRet Recall@10 77.95、SRA-Bench Recall@10 83.78，超过对应的 concatenated learned baselines。作者还发现技能库越大，field-aware 表示的优势越明显。

**可迁移价值**：适合用于设计 agent skill registry：索引时保留 name、description、trigger、body、examples、constraints 等字段；召回时把字段级相似度交给轻量学习器融合，而不是只存一个 embedding。

**局限**：目前主要验证检索排序，没有完整评估“检索错技能后 agent 执行任务失败”的端到端损失；SRA-Bench/SkillRet 与真实工作区工具生态仍有差距。

### 4. ISEE: Interactive Semantic Enrichment for Database Fields

- 链接：https://arxiv.org/abs/2608.02604
- 方向：General Agent / Data Agent / Human-in-the-loop Context
- 评分：4.360
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：企业数据 agent 常要做 entity linking、自然语言查库和数据探索，但数据库字段说明往往含糊、缺失或依赖内部业务知识。LLM 不能从公开知识中可靠推断这些私有语义，结果会把用户问题映射到错误字段。

**核心方法**：ISEE 把字段语义补全做成一个交互系统，包含 Evaluation、Clarification、Enrichment 三个阶段。系统先用 downstream-aware scoring 评估字段描述质量，再通过澄清问题向领域专家索取缺失知识，最后把用户反馈整合成更完整的字段说明。它不是一次性让 LLM 猜字段含义，而是把“我不知道什么”变成可交互的问题。

**创新点**：对 agent 系统的启发在于：当上下文来自私有环境时，自动补全不如显式发起 clarification。它把 domain expert feedback 纳入数据语义构建流程，可迁移到代码仓库 agent 的配置字段解释、内部 API 语义补全和企业检索 schema grounding。

**实验与 benchmark**：论文报告用户研究、自动用户模拟、定量评估和 case study。用户研究中，ISEE 相比 manual editing、candidate selection、ChatGPT 分别提升描述补全准确性 119%、32%、92%，并降低认知负担；定量评估显示 enriched descriptions 相比自动 enrichment 让 entity linking 提升 22%、text-to-SQL 提升 12%。自动用户模拟使用 BIRD text-to-SQL 数据集，指标包括 entity linking 的 MRR 和 SQL execution accuracy。

**可迁移价值**：可用于数据/代码 agent 的“语义记忆生成”：先评估上下文说明质量，再生成澄清问题，再把回答写回可检索说明，而不是把缺失上下文交给模型幻觉填补。

**局限**：强依赖领域专家反馈；交互成本和用户耐心在大规模字段库中可能成为瓶颈。

### 5. RAG-Stack: Co-Optimizing RAG Serving Performance and Quality

- 链接：https://arxiv.org/abs/2608.03487
- 方向：Search Agent / RAG Systems / Quality-Cost Optimization
- 评分：4.275
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：RAG 系统有大量配置：索引、召回轮数、reranker、生成模型、serving 硬件和部署参数都会影响质量、延迟和吞吐。手工调这些配置成本高，且同一个配置在不同数据集和硬件上未必维持 Pareto 最优。

**核心方法**：RAG-Stack 包含三个组件：RAG-PE 是设计空间探索算法，选择下一组值得评估的 RAG 配置；RAG-IR 是工作负载抽象，用来统一表示不同 RAG 算法；RAG-CM 是性能模型，预测给定硬件上的最优部署与 serving performance。它的目标不是最大化单一质量指标，而是在 algorithm-system 联合空间中找质量-性能 Pareto frontier，并支持把已有 frontier 迁移到新 serving system。

**创新点**：它把 Search/RAG Agent 从“答案质量”推进到“质量、延迟、吞吐和部署成本联合优化”。对于真实 agent 平台，检索深度、重排强度和长上下文长度都应该由系统根据预算搜索，而不是固定在 prompt 模板里。

**实验与 benchmark**：摘要和前 8 页显示，在多数据集、相同优化迭代次数下，RAG-Stack 找到的 Pareto frontiers 覆盖的归一化质量-性能空间比 state-of-the-art configuration-search 方法多 52.5-153.2%。论文还明确释放 artifact：https://github.com/haiqiang-zhang/rag-stack。

**可迁移价值**：可用于训练 agent runtime policy：把“是否再检索、是否 rerank、是否换更大模型、是否压缩上下文”变成有成本模型的配置搜索问题。

**局限**：它优化的是 RAG serving pipeline，不直接覆盖多步网页浏览 agent；质量评估和硬件性能模型迁移到开放互联网搜索仍需验证。

### 6. SciRet: A Compute-Aware Empirical Study of Retrieval and Reranking for Scientific RAG

- 链接：https://arxiv.org/abs/2608.03860
- 方向：Search Agent / Scientific RAG / Retrieval Evaluation
- 评分：4.035
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：科学文献 RAG 对术语、证据和引用要求高，通用网页 QA 中有效的 reranker 未必适合科学语料。很多小规模 RAG 实验只看 1K 级 corpus，无法说明系统扩展后行为是否稳定。

**核心方法**：SciRet 固定一个科学 RAG pipeline，在 CORD-19 的 1K、5K、15K 三个语料规模上比较检索与重排。pipeline 包括 sentence-window chunking、BM25、BGE-M3 dense retrieval、reciprocal rank fusion、可选 cross-encoder reranking 和 grounded answer generation。

**创新点**：这篇主要是可复现实证，而不是新模型。它提醒 Search Agent 训练/评估要把计算预算纳入设计，并检查 reranker 的 domain mismatch：更强的 cross-encoder 如果训练域不匹配，可能降低科学语料 precision。

**实验与 benchmark**：论文使用 CORD-19，语料规模分别为 1,034、5,160、15,480 chunks。结果显示 hybrid retrieval 在该设置下比 sparse-only 或 dense-only 更鲁棒，在 1K 和 15K 达到 Recall@10=1.000；但 MS MARCO 训练的 cross-encoder reranker 在科学 corpus 上降低 precision。作者明确把结果视为受控比较证据，而不是完整 benchmark claim，因为评估用 hybrid top-3 派生的 pseudo-relevance labels，query 只有 15 个。

**可迁移价值**：适合作为 research agent 的检索基线：先构建可复现实验脚手架，再逐步替换 chunking、召回、reranking 和 answer grounding，避免只凭单次 demo 判断检索策略。

**局限**：只索引标题和摘要，不包含全文、表格和图；pseudo labels 可能偏向 hybrid retrieval；查询规模较小。

## Code Agent

### 7. GenOS: Compositional Certificates for Semantic Robustness in AI Code Generation

- 链接：https://arxiv.org/abs/2608.03588
- 方向：Code Agent / Semantic Robustness / Validation Workflow
- 评分：4.590
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：AI coding agent 是随机工作流：prompt 被解释，候选代码被采样，validator 返回观察，orchestrator 决定提交或修复。小的 prompt 或 spec 改写可能让行为分布变化，即使文本看起来等价。现有 benchmark 多评 correctness，却缺少判断“替换 prompt、contract、generator 或 program 后，整个工作流是否仍语义等价”的组合准则。

**核心方法**：GenOS 用概率操作语义描述代码生成工作流。每一层都是 Markov kernel，每个语义接口带有 observer-relative equivalence，说明下一层允许忘记哪些差异。论文证明 equivalence-compatible kernel 可以下降到 quotient classes，且 quotienting 与 distributional extension、sequential composition 交换；进一步给出 workflow-bisimulation、guarded-commit safety、total-variation non-expansiveness 和 additive robustness bound。

**创新点**：它把 coding agent 的鲁棒性从“测试是否通过”提升到“接口替换在观察者定义下是否保持分布等价”。这对代码 agent 很关键：prompt paraphrase、validator 变更、修复策略变更都可能改变 commit 概率，GenOS 提供了把这些变化局部化计量的语言。

**实验与 benchmark**：论文提供 executable insertion-sort audit：包括自然语言 paraphrases、formal contract、6 个具体程序、2 类 program observers，并在 121 个输入上穷举执行。它更像形式化审计样例，不是大规模 SWE-bench 类 benchmark。

**可迁移价值**：可用于设计 code-agent 回归测试：把 prompt/spec/validator 的替换看成 workflow 层的变更，要求 verified commit 这类 equivalence-closed event 的概率保持稳定，并把缺陷分摊到具体层。

**局限**：形式化贡献强，但实证规模小；要落到真实仓库修复 agent，还需要把 observer、equivalence 和 validator soundness 工程化。

### 8. BBOWP-Bench: Evaluating LLMs on Black-Box Optimization Word Problems

- 链接：https://arxiv.org/abs/2608.02612
- 方向：General Agent / Code Agent / Executable Benchmark
- 评分：4.080
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：很多真实问题不能把目标函数写成显式数学表达式，只能运行黑盒环境拿到分数。LLM 要自动求解这类任务，必须从自然语言描述中同时推断搜索空间和优化算法，而不仅是生成一段公式。

**核心方法**：论文定义 Black-Box Optimization Word Problems，并构建 BBOWP-Bench。每个实例包含自然语言问题描述、可执行评价环境、人工设计的参考 formulation；系统要输出优化算法和 search space，然后通过真实 black-box optimization runs 评估。候选算法包括 TPE、CMA-ES 等，任务描述还包含 evaluation budget。

**创新点**：对 agent training 的价值在于它把“理解任务 -> 构造可执行搜索空间 -> 选择算法 -> 运行环境评估”连成闭环。这比只答数学题更接近真实工具使用，尤其适合训练会把模糊需求转成可运行实验的 code/general agent。

**实验与 benchmark**：BBOWP-Bench 覆盖 23 个实例，来自 YAHPO Gym、Olympus、MECHBench 和 MuJoCo 四类应用域。论文评估多个 LLM，发现当前模型能根据预算选择合适算法，但在搜索空间设计上仍会出错，尤其是问题描述信息不足或变量范围高度依赖领域知识时。

**可迁移价值**：可以把它改造成 agent 环境合成模板：自然语言需求不是直接映射答案，而是映射到可执行配置空间和 evaluator，奖励来自运行结果。

**局限**：任务偏优化建模，不是通用软件修复；自动构造 search space 的错误诊断还需要更细粒度标签。

### 9. Can Large Language Models Recover Semantic Optimization Opportunities That Compilers Miss?

- 链接：https://arxiv.org/abs/2608.03983
- 方向：Code Agent / Compiler Optimization / Validated Artifacts
- 评分：4.030
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：C/C++ 编译器只能利用编译表示中可证明的语义。跨函数上下文、数据结构不变量或高层等价关系如果没有进入编译分析，优化机会就会被错过。问题是 LLM 是否能从 heterogeneous C/C++ context 中恢复这些隐藏语义，并把它们变成可验证、保持 contract 的 artifact。

**核心方法**：论文提出 SeGaBench，包含 100 个 synthetic cases 和 20 个 source-backed cases。每个 case 有隐藏 enabling semantics、oracle artifact、correctness/semantic validators 和可复现实验协议。模型需要恢复语义、生成 artifact，并通过验证与性能测试。

**创新点**：它把 LLM 放在“speculative semantic proposer”的位置：LLM 负责提出可能的语义 artifact，validator 负责建立正确性，编译器负责下游优化。这正是 code agent 可控落地的一种形态：模型不直接替代编译器或测试，而是在强验证边界内提出候选。

**实验与 benchmark**：论文评估 5 个 LLM，每个 case 采样 5 次，共 3,000 请求。最强模型达到 95.0% semantic recovery、94.8% correct artifacts、83.3% E2E@1.05 性能成功，并在 93.3% cases 上五次采样至少一次成功。指标包括 schema compliance、artifact generation、compilation、functional validation、semantic validation 和 speedup。

**可迁移价值**：适合用于 code agent 的“生成候选 + 验证器裁决 + 性能协议”训练数据。关键启发是把自然语言推理结果落成可执行 artifact，并且要求 contract-aware fallback。

**局限**：benchmark 与编译优化强绑定；真实项目中的性能噪声、平台差异和未建模 invariant 会增加失败率。

### 10. Reinforcement Learning with Evolving Rubrics as Rewards for Audio Reasoning

- 链接：https://arxiv.org/abs/2608.02831
- 方向：General Agent / RL Reward Design / Process Supervision
- 评分：3.980
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：可验证奖励能提升推理，但只看最终答案会允许模型走捷径，尤其在音频任务中可能不真正关注 acoustic evidence。固定 process reward 又过于粗糙，且当策略提升后会饱和。

**核心方法**：AudioRubrics 为每个样本从原始 waveform 合成细粒度、audio-grounded rubrics，并根据模型 rollout 重新生成和重加权 criteria。训练中同时使用 outcome reward 和 evolving rubric reward，并加入 reasoning length penalty，避免推理轨迹塌缩或无限变长。

**创新点**：虽然任务是音频，但 reward 设计对 General Agent 很有迁移价值：评价标准不固定，而是随当前 policy 的错误模式更新；process supervision 不是人工写死模板，而是按样本和 rollout 生成。

**实验与 benchmark**：论文在 MMAU、MMAR、MMSU 三个 audio reasoning benchmark 上评估，并与开源模型及 RL baseline 对比。前 8 页显示 AudioRubrics consistently outperforms baselines，且分析表明 rubrics 会随 policy 改进变得更高级，推理长度趋于稳定。

**可迁移价值**：可以用于 tool-use RL：为每条轨迹生成“证据是否被读取、工具是否必要、观察是否被利用、下一步是否合理”等动态 rubrics，再随 agent 能力提升调整权重。

**局限**：领域是音频推理，不直接评估网页搜索或代码执行；rubric generator/judge 的能力会显著影响训练信号。

## 今日重点趋势

1. Search Agent 正从“相似度召回”转向“结构化检索接口 + 证据集合评价”。SIEVE 和 RubricRanker 都说明，agent 需要能操作网页/文档结构，并需要 query-specific rubrics 来判断证据集合是否足够。
2. Skill 与 context 管理成为 agent 长期运行瓶颈。Field Aware Agent Skill Retrieval 和 ISEE 都强调，不要把结构化知识压扁成一段 embedding；字段、说明质量、澄清问题和用户反馈本身都应进入可检索状态。
3. Code Agent 的可靠性正在走向“生成后验证”和“语义接口约束”。GenOS 与 SeGaBench 都把 validator/observer 放在核心位置，提示 code agent 后训练应该显式建模验证器观察，而不是只学补丁文本。
4. RAG/Search 系统开始把成本作为一等目标。RAG-Stack 和 SciRet 都说明，检索深度、rerank 强度、语料规模和硬件延迟需要联合评估。

## 潜在研究 idea

1. 构建 Search Agent 训练轨迹时，把 `query -> BQL/field constraints -> result card inspection -> section fetch -> citation` 作为标准动作序列，并把 token cost 纳入 reward。
2. 为 agent skill bank 建一个 field-aware retriever：分别索引 skill 名称、触发条件、限制、步骤和示例，用轻量 MLP 或 listwise reranker 融合字段分数。
3. 把 RubricRanker 的 query-specific rubrics 扩展到代码修复：每个 issue 自动生成 correctness、minimality、test coverage、risk、style consistency rubrics，再作为 patch reranking reward。
4. 用 GenOS 的思路做 prompt/validator 回归测试：当 prompt 或测试 harness 改动时，要求 verified commit、test failure diagnosis 等关键事件分布不能异常漂移。
5. 在 RAG agent runtime 中引入 Pareto controller：根据问题难度动态选择是否二次检索、是否使用 reranker、是否进入长上下文模型。

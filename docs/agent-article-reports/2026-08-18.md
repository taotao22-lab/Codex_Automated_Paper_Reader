## 今日概览

今日候选池来自 arXiv recent-list，目标日期为 2026-08-18，共 89 篇；OpenReview HTTP fallback 对 ICLR、NeurIPS、ICML、TMLR 返回 403，对 COLM 返回 403/429，因此今日 Top 10 只来自 arXiv。筛选重点放在 Code Agent 的仓库级修复与测试闭环、Search Agent 的 GraphRAG/多跳检索/混合检索评测，以及 General Agent 的长期记忆与可验证工具调用。

## Top 10

### 1. Kozuchi Agent: A Language-Agnostic Open-Weight Agent for Software Repair

- 方向：Code Agent / 软件修复 / SWE-bench
- 评分：4.91
- 证据来源：arXiv PDF 前 8 页 + 摘要

这篇最贴近仓库级 Code Agent。它不是单纯换一个更强模型，而是把软件修复 agent 拆成可审计的工程流水线：显式阶段控制、持久状态、确定性工具、模型无关 action interface，以及跨 agent 的 test-time selection。论文强调真实修复任务包含复现 bug、生成回归测试、定位根因、多文件编辑、验证结果等长链路，如果让模型自由规划，容易跳过复现、重复调查或在没有理解代码时直接改文件。

创新点在于它把“agent 能力”外化为运行时协议和 CI 产物。模型可以是本地 Qwen3.5-27B，修复流程由 harness 约束；工具调用语法差异由接口层吸收；多集群运行和 Docker grading 被 CI 阶段复用。对训练数据构造的启发是：可以把成功/失败轨迹按阶段切分，明确哪些失败来自语义修复、测试选择或 harness 问题，而不是只记录最终 patch。

实验与 benchmark：SWE-bench Verified 500 题上，使用本地 Qwen3.5-27B、无微调、TTS@8，解决 374/500；Multi-SWE-bench Java 上解决 41/128，论文称在 strict open-weight 提交中排名第一。局限是前 8 页主要说明系统设计和 benchmark 背景，失败分析细节没有完全展开；摘要提到剩余失败主要是语义正确性、Java harness 问题和选择错误。

阅读建议：强烈建议精读。它可直接启发 Code Agent post-training 的阶段标签、工具接口规范、CI 复用和候选 patch 选择器训练。

### 2. TDD-Agent: Test-Driven Reasoning for Code Generation

- 方向：Code Agent / 测试驱动生成 / 执行反馈
- 评分：4.74
- 证据来源：arXiv PDF 前 8 页 + 摘要

TDD-Agent 的核心观点是：测试不应该只是生成代码之后的静态 validator，而应成为模型推理的一部分。框架先让模型生成可执行测试，使输入约束、边界情况和预期行为显式化；随后在同一个 agent 的历史上下文中，同时迭代修复代码和测试，并用执行反馈校正两者。

创新点在“dual-track refinement”：传统 self-generated tests 容易有偏，错误测试会误导实现；TDD-Agent 不把测试固定下来，而是允许测试本身随着执行结果被审查和修正。对 Code Agent 训练很有价值，因为它把需求理解转化为可运行的中间表示，适合形成“先写意图测试 -> 写实现 -> 跑测试 -> 修改测试或代码”的轨迹数据。

实验与 benchmark：论文在 LiveCodeBench 上用 TDD-prompt 隔离 test-first reasoning 的效果；在 RepoEval 仓库级任务上评估完整 TDD-Agent，并称超过 retrieval-based 和 agent-based baseline。摘要还报告迭代 refinement 提升 pass rate、coverage 和 mutation score。前 8 页没有给出完整数值表，因此日报不编造具体提升幅度。

阅读建议：优先读方法和实验章节。它适合迁移到 SWE-bench 训练：把测试生成质量、覆盖率、mutation score 作为过程奖励，而不仅是最终 hidden tests。

### 3. LineageRAG: Harnessing GraphRAG by Constructing Evidence Lineages with Source Grounding

- 方向：Search Agent / GraphRAG / 多跳证据链
- 评分：4.62
- 证据来源：arXiv PDF 前 8 页 + 摘要

LineageRAG 解决 GraphRAG 的一个关键缺口：图检索能找到候选证据，但最终证据集合经常丢失“这个 passage 是为满足哪个 evidence demand 而来”的来源关系。论文把每个 query-derived evidence demand 作为一条 evidence lineage，从需求生成、图上扩展、候选合并到最终 verbatim source span grounding 都保留需求身份。

核心方法分三步：先从问题中诱导 evidence demands；再按 demand 条件在 corpus graph 上扩展候选，并在合并时保留 demand-passage 关联；最后用 lineage provenance 选择互补 passages，并抽取能支撑该 demand 的原文 span。直观地说，它不是把 Top passages 混在一起给 LLM，而是要求每条证据链都说明“我在回答哪一个子需求，源文是哪一句”。

实验与 benchmark：HotpotQA、2WikiMultiHopQA、MuSiQue。摘要报告相对 leading GraphRAG baselines 平均提升 R@5 3.51、EM 5.96、F1 5.22。论文前 8 页展示了 HotpotQA failure case：普通 whole-question ranking 漏掉第二跳 passage，而 LineageRAG 通过分开的 demands 找回完整链路。

阅读建议：非常适合 Search Agent。可迁移实验是把 search trajectory 标注成 demand-level lineage，用作检索策略 SFT/RL 的中间监督，并把 source span grounding 作为引用可信度奖励。

### 4. Noesis: Bidirectional Graph-RAG with Adaptive Parallelism and Cross-Knowledge-Base Semantic Discovery

- 方向：Search Agent / GraphRAG 系统 / 跨知识库路由
- 评分：4.60
- 证据来源：arXiv PDF 前 8 页 + 摘要

Noesis 是偏系统型的 GraphRAG 论文，目标是解决生产 RAG 的三个瓶颈：静态 chunking 破坏长文跨段关系；固定并行度导致 OOM 或硬件利用不足；多知识库部署需要用户手动路由或合并成一个污染上下文的大库。

它提出四个组件：双向图遍历和 Graph-Feedback Context Resolver，用 n-gram scoring 与 recency decay 模拟带遗忘的人类顺序阅读；AIMD Concurrency Controller，把 TCP 拥塞控制思想迁移到 RAG ingestion 并用 Redis 保持状态；Moesis，对 MoE 模型做领域感知选择性量化；Mesh，用层级 fingerprint 和运行时结构发现做跨 KB semantic routing。这个设计对 Agent 的价值在于：检索系统本身开始具备“可恢复、可扩展、可路由”的运行时控制。

实验与 benchmark：HotpotQA 1,000 问题上报告 59.5 EM / 74.7 F1，比 GraphRAG 高 27.8 EM；13.4MB corpus ingestion 从 25 分钟降到 1 分 6 秒；Moesis 在 12GB consumer GPU 上 prompt processing 6.3x；跨 KB routing latency 小于 2ms；193 页文档上的 long-range causal edges source verification precision 为 90%。局限是系统包含 patent pending 声明，且前 8 页更多是架构和摘要级结果，细粒度复现实验需继续读后文。

阅读建议：适合作为 Search Agent 工程参考，尤其是检索 ingestion 的自适应并发和跨知识库路由。

### 5. T-LLM Compiler: Trusted LLM-based Code Optimization and Verification Framework

- 方向：Code Agent / 编译器优化 / 验证闭环
- 评分：4.52
- 证据来源：arXiv PDF 前 8 页 + 摘要

这篇论文把 LLM 用在代码优化，但关键不是“让模型直接重写代码”，而是让 LLM、传统编译器和验证工具协同。作者把编译器 AI 化分成多个 level：传统启发式是 level 0，ML 预测优化收益是 level 1，LLM 做高层源码改写是 level 2，更复杂的 LLM transformation sequence 是 level 3，工具广泛集成的优化流程是 level 4。T-LLM Compiler 属于把 LLM 改写纳入验证闭环的方向。

对 Agent 研究的启发在于：代码 agent 的动作空间可以不局限于 patch issue，也可以是“提出优化变换 -> 编译器处理 -> 验证正确性 -> 失败后 corrective action”。这种任务天然有执行反馈和 correctness gate，适合做强化学习或 rejection sampling。

实验与 benchmark：PolyBench/C。摘要报告最高 code optimization accuracy 83.3%，最高 speedup 16.1%，相对标准 baseline 平均 speedup 26.7%。前 8 页没有完整表格和验证工具细节，因此这些数值按摘要引用。

阅读建议：适合关注 tool-use reasoning 和可验证 code transformation 的读者。后续可把它和 SWE-bench 的 patch verification 统一成“外部工具给 reward/certificate”的训练框架。

### 6. From Errors to Proofs: Minimal-Core-Guided Repair for Neuro-Symbolic Constraint Solving

- 方向：General/Code Agent / solver 工具调用 / proof-guided repair
- 评分：4.50
- 证据来源：arXiv PDF 前 7 页 + 摘要

这篇解决的是 LLM + symbolic solver 流程中的沉默失败：程序能运行，但 formalization 不忠实，solver 只是忠实地解错问题。传统自修复多依赖 parse/runtime error；如果程序 well-formed 但过约束或漏约束，错误消息不会指出语义问题。

方法是把 repair signal 从“错误消息”换成“证明”。模型把自然语言约束题翻译成 Answer Set Programming；当程序不可满足时，系统抽取模型自身约束上的 minimal unsatisfiable core，把最小冲突约束集反馈给模型。这是 leakage-free 的，因为它来自模型生成的程序，而不是答案 oracle。直观上，它告诉模型“你写出的这几条约束不能同时成立”，比“无解”更能定位翻译错误。

实验与 benchmark：新 benchmark 77 个问题、7 个领域、带 exact oracle；翻译到 ASP 在 6/7 个领域 faithful，失败集中在 aggregate-coverage scheduling。摘要报告 minimal core 把较弱模型对 infeasible problems 的 fabrication 从 79% 降到 7%；直接 prompting 对 infeasible problem 仍有 21% fabrication。强 CoT baseline 在 accuracy 上接近 symbolic route，所以作者强调 symbolic route 的价值是 certificate 和拒绝编造。

阅读建议：值得加入 tool-use RL 的相关工作。它提供了比 pass/fail 更结构化的负反馈，适合训练 agent 在 formal tools 返回证据时修复自身 specification。

### 7. Mental Model Management: An Operator-Based Framework for LLM Memory

- 方向：General Agent / 长期记忆 / 概念模型
- 评分：4.39
- 证据来源：arXiv PDF 前 8 页 + 摘要

3M 不是一个追求 benchmark SOTA 的系统，而是一个 agent memory 框架。它反对把长期记忆简单做成 passage/chunk 堆栈，主张把记忆组织成 concept-centered mental models：每个 mental model 由短小、可修改的 chunks 构成，可以表示事实、关系、规则、观察、过程、假设或推导原则。

核心方法是定义一组显式 operators：抽取知识、检索相关模型、添加/更新 chunk、重组表示、检测不一致、派生新知识。新信息进入系统时，不是简单 append 到 memory，而是触发扩展、合并、拆分、连接、压缩、纠错、抽象等操作。这个视角与 MemGPT、MemoryBank、Generative Agents、A-MEM 相连，但把重点放在“持久概念表示如何被变换”。

实验与 benchmark：前 8 页主要是框架定义和 Evolution Strategies running example，没有发现标准 benchmark 或量化结果。局限很明确：更像概念/架构论文，需要后续实现和评测。

阅读建议：适合做 Agent 长程任务记忆设计的 taxonomy。可转化实验是把任务轨迹压缩成 concept models，并训练模型选择 memory operator，而不是只训练检索 query。

### 8. ATLAS: Scaffold-Free Algorithm Synthesis by LLMs via Embedding-Guided Quality-Diversity Search

- 方向：General/Code Agent / 自动算法设计 / 质量多样性搜索
- 评分：4.49
- 证据来源：arXiv PDF 前 8 页 + 摘要

ATLAS 关注 LLM 自动算法设计。已有 FunSearch、EOH、REEVO 等方法通常在人工 scaffold 中优化一个指定组件，例如 priority function 或 scoring rule；ATLAS 让 LLM 生成完整可执行算法，只固定问题 specification、objective/constraints 和最小 I/O interface，算法内部组件、控制流和交互由模型自由设计。

这种自由会带来大量无效候选和模式坍缩，所以 ATLAS 加了三类机制：独立检测 execution/interface/feasibility failure，并用 error-conditioned repair 修复；用 embedding-space archive 保留不同设计区域的高质量算法，避免过早收敛；用三层搜索分别精修最优设计、给其他区域专门 refinement 机会、跨区域合成组件。对 Agent 训练的启发是：当动作空间从“填一个函数”扩大到“设计完整流程”，需要 archive、多样性和可执行失败分类共同约束。

实验与 benchmark：摘要称跨 4 个 NP-hard problems，ATLAS 超过多个 state-of-the-art component-synthesis methods 和匹配的 full-synthesis baseline，并与强 human-designed algorithms 竞争。前 8 页没有完整问题列表和数值表，因此不展开具体指标。

阅读建议：适合用于环境/任务合成、工具链自动设计和 agent scaffold 进化；尤其值得看它如何把 embedding diversity 变成搜索控制信号。

### 9. Dense Expands, Sparse Anchors: Channel-Asymmetric Query Expansion for Hybrid Retrieval

- 方向：Search Agent / 混合检索 / 查询扩展
- 评分：4.34
- 证据来源：arXiv PDF 前 8 页 + 摘要

DESA 针对 hybrid retrieval 中 LLM query expansion 的一个实际问题：生成文本既可能补充语义，也可能污染稀疏检索的词面支持；而多数论文只在固定 top-L 下融合 dense/sparse ranking，导致扩展收益随 cutoff 变化甚至反转。

方法采用 channel-asymmetric design。dense 侧用 LLM 生成 complementary reference passages，再通过 orthogonal residual expansion 保留原查询方向，只添加新语义方向；sparse 侧用 score-product anchoring，把原查询和扩展查询的得分相乘，使只被生成词命中的文档拿不到 anchored score，但生成词仍可在原查询支持的文档中重排。直观说就是 dense 负责扩展语义，sparse 负责锚定原始证据。

实验与 benchmark：7 个 BEIR datasets。摘要报告相对 unexpanded query，nDCG@10 提升 3.82%，Recall@20 提升 2.38%；dense/sparse access depths 分别下降 36.90% 和 36.56%；按数据集等权，63.31% queries 在两个通道都更浅。局限是 Contriever on Touché-2020 上两个 depth 都增加，说明扩展策略和 retriever/dataset 强相关。

阅读建议：适合 Search Agent 的查询规划训练。可以把 access depth 作为成本奖励，让 agent 学会何时扩展、扩展给哪个检索通道。

### 10. The Commercial Tax: Rent-vs-Own Blind Spots in Multi-Hop Retrieval Benchmarks

- 方向：Search Agent / 检索 benchmark / 商业可部署性
- 评分：4.27
- 证据来源：arXiv PDF 前 8 页 + 摘要

这篇不是新检索算法，而是对多跳检索 benchmark 的可部署性审计。作者指出 MuSiQue 等 multi-hop retrieval 榜单依赖的 dense-retrieval anchor NV-Embed-v2 是 cc-by-nc-4.0 非商业许可；被审计的 HippoRAG-2、PropRAG、SAG、KET-RAG 中，多数最佳结果依赖它但没有明确暴露商业部署限制。对企业 Search Agent 来说，benchmark 数字如果不区分 license 和 indexing cost，会误导系统选型。

方法上，论文在统一 MuSiQue harness 上比较 8 个厂商的 13 个 embedder，并用 bootstrap confidence intervals 报告 Recall@5/10；同时审计 graph construction 和 embedding indexing 成本，把 one-time indexing cost 与 recurring answering cost 分开。

实验与 benchmark：MuSiQue 1,000 问题。摘要称 2026 年中以前存在 commercial tax：最佳商业许可 embedder 比 anchor 低 2.31 Recall@5；NVIDIA Nemotron-3-Embed-8B 发布后在 Recall@5 上与 anchor 统计不可区分。成本方面，GraphRAG 相关公开数字在 5.64MB corpus 上可相差 11x，线性外推到 1TB 可从约 428K 美元到 4.6M 美元一次 indexing。局限是 vendor adoption 数字只作为方向性引用，作者也强调不是依赖其精确值。

阅读建议：适合 related work 和系统评估章节。它提醒 Search Agent benchmark 应同时报告 license、self-hosting、indexing cost、answering cost 和 retrieval quality。

## 其他值得关注

- Evolving Executable Pipeline Programs for AutoML with Language Models：LACE 把 AutoML 搜索空间改成完整 scikit-learn-compatible Python pipeline program，在 68 个 OpenML classification tasks 上与 AutoGluon 接近、超过 auto-sklearn/H2O/fixed XGBoost。它对“可编辑程序作为搜索对象”很有启发，但相对 Agent 主题稍偏 AutoML。
- When Is Complex Chunking Worth It?：在 CoRE 与 KILT/NQ 可扩展语料、3 个开源 embedder 和多种 corpus size 上比较 8 种 chunking 策略，同时报告 NDCG@10、Recall@100、throughput 和 memory。结论是复杂 chunking 很少稳定超过简单方法，适合做 RAG 工程 baseline。
- Ask to Be Sure：多轮推荐中的 informative interaction 与置信度建模，和 Search Agent 的澄清式查询有弱相关，但推荐系统场景占主导。

## 今日重点趋势

1. Code Agent 的高价值反馈越来越来自外部可执行系统：tests、compiler、solver、CI grader。训练时应保留这些反馈的结构，而不是只压成 pass/fail。
2. Search Agent 的核心不只是召回更多 passage，而是保留 evidence demand、source span、license/cost/access depth 等可审计元数据。
3. 长期记忆和自动算法设计都在从“文本记录”转向“可操作对象”：concept model、pipeline program、algorithm archive、evidence lineage。

## 潜在研究 idea

1. Demand-lineage search RL：让 Search Agent 先生成 evidence demands，再对每条 demand 维护检索 lineage；奖励由 answer correctness、source span grounding 和未满足 demand 惩罚组成。
2. Test-as-reasoning Code Agent：把 TDD-Agent 的测试先行和 Kozuchi 的 CI 阶段结合，构造包含 test intent、execution log、patch diff、selector decision 的训练轨迹。
3. Proof-guided tool repair：把 minimal unsat core、compiler verification failure、unit test failure 统一成 structured feedback schema，训练模型根据证据选择“改 specification / 改 code / 改 test / 放弃”。
4. Cost-aware Search Agent：在 DESA 的 access depth 与 Commercial Tax 的 indexing/answering cost 基础上，把检索策略优化成质量-成本双目标问题。

## 值得加入 related work

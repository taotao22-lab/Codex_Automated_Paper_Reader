## Code Agent

### 1. Persistent Recursive Worlds Enable Autonomous Software Evolution

- 问题背景：论文讨论的是长周期软件项目和短生命周期 coding agent 的错配。已有系统多依赖长会话、外部 memory、manager agent 或共享上下文来维持连续性，但软件项目真正需要保留的是接口、测试、历史约束、失败经验和可接受变更，而不是某个 agent 本身。
- 核心方法：EvoX Genesis 把软件项目表示成 persistent recursive world。每个局部世界由已接受版本和仓库路径定位；短生命周期 agent 只在局部路径中承担有限任务；上层 agent 可以递归委派任务；只有通过验证和审查的后果才进入持久版本历史。直观地说，它把“长期记忆”从 agent 脑子里搬到项目世界中，让每一轮 agent 都从项目的已接受状态重新进入。
- 创新点：新意不在单个补丁生成，而在把软件演化建模为持久项目状态、递归局部工作和 accepted consequence 的组合。这对 agentic post-training 很有启发：训练数据可以围绕“局部任务、验证、接受/拒绝、版本推进”来组织，而不是只记录最终 diff。
- 实验与 benchmark：PDF 前 8 页给出三个评估阶段。Formation 从空仓库构建 Rust C 编译器，运行超过 123.4 小时，归档 1,019 个 agent episodes，达到 delegation depth 5；外部评估包含 c-testsuite、LLVM test programs、LZ4、SQLite、Csmith，以及 2,904 个 Rust workspace tests。Continuation 测试模型替换后的继续开发，GLM 5.2 分支通过 1,445/1,448 LLVM cases，DeepSeek V4 Flash 分支通过 1,820/1,820。Redevelopment 将 MESA 13 个模块重写为 Rust workspace，前 8 页显示运行 33.22 小时、272 个 agents、89,946 行 Rust、通过 1,052 个测试，并报告 6 个数值 workload 的加速。
- 可迁移价值：可直接迁移到 Code Agent 训练环境设计：把 repo path、accepted version、validation record、delegation trace 作为状态；把“被接受的后果”作为奖励或偏好信号；把失败变更作为反例。它也提示长程 agent 不一定要扩大单次上下文，而可以让项目状态成为跨 episode 的承载物。
- 局限：论文自己说明实验是能力展示，不是严格模型对照；成本只统计 provider token cost，不含硬件、存储、控制器和人工成本；不同 continuation 分支的测试集和预算不完全一致。
- 阅读建议：强烈建议精读。特别关注 persistent world 的状态定义、验证门控、递归委派和 lineage 记录，这些可以变成后训练轨迹 schema。
- 证据来源：arXiv PDF 前 8 页和摘要。

### 2. Understanding the Architecture of Coding Agents: An Exploratory Study Using a Research Prototype

- 问题背景：coding agents 已经成为 AI-assisted software development 的主要界面，但其内部架构还缺少类似编译器或操作系统那样的系统化描述。没有清晰架构，研究者很难比较 memory、tool invocation、workspace management、patch application 等模块。
- 核心方法：论文构建了一个研究原型 Ark，用简洁系统暴露 coding agent 的核心组件：任务控制、代码上下文收集、工具调用、agent memory、workspace 管理和安全修改应用。它不是为了击败商业 agent，而是把现代 coding agent 的机制拆成可教学、可实验的模块。
- 创新点：贡献在“可解释架构样机 + 轻量 benchmark”的组合。对研究而言，这比单纯 benchmark 分数更有用，因为它把 agent 行为拆成可以替换、消融、记录的部件。
- 实验与 benchmark：论文引入 ArkBench，包含 10 个代表性软件维护和演化任务。PDF 摘要页显示 Ark 使用 gpt-5.4-mini 解决 8/10 个任务，并用 modest token consumption 完成。它还用一个 coding-agent architecture taxonomy 对比 Ark 和 state-of-the-art agents。
- 可迁移价值：适合作为 Code Agent 系统课程和实验基线。可以把 ArkBench 任务改写为内部 sandbox task，用来评估 tool routing、patch safety、memory 策略和 workspace 隔离。
- 局限：benchmark 规模只有 10 个任务，主要价值是研究原型与分类框架，不应过度解读为能力排名。
- 阅读建议：建议和 Genesis 一起读：Ark 关注单个 agent 架构，Genesis 关注跨 episode 的项目连续性。
- 证据来源：arXiv PDF 前 8 页和摘要。

### 3. Do Personalized Skills Help Coding Agents? An Empirical Study of Developer Interaction Histories

- 问题背景：开发者长期和 coding agent 协作会形成偏好，如沟通风格、验证习惯、提交约定、实现偏好。一个自然想法是从个人历史中抽取 personalized skills，让 agent 复用偏好。但问题是：个人技能真的比通用技能更好，还是只是增加了额外上下文和执行成本？
- 核心方法：论文从真实 developer-agent 交互轨迹中抽取技能。流程包括 rule-based bootstrapping、evidence-grounded refinement，以及一个可复现 replay framework；评估时用 trajectory-conditioned LLM-based human developer simulator 模拟互动反馈。
- 创新点：它没有假设“个性化一定好”，而是把 skill 作为可检验的程序性知识单元，并区分 personalized skill、generic skill、random developer skill、no skill 四种条件。这对技能库建设很关键：不是所有历史都值得个性化，频繁且可复用的偏好才有价值。
- 实验与 benchmark：实验覆盖 206 个真实 developer-agent sessions、13 名开发者。PDF 前 8 页显示，personalized skill 平均只把 task-completion score 从 65.02 提到 65.99，但会增加 tool calls、tokens、code changes 和 validation attempts；generic skill 最稳定。只有当至少 6 个相关历史 session 可用时，personalized skill 才明显优于 no-skill 和 random-user skill，并在该组超过 generic skill。模拟器语义一致性至少部分匹配真实消息的比例为 89.47%。
- 可迁移价值：对 Codex skill / memory 系统非常直接。建议把技能抽取分成“通用流程规则”和“高频个人偏好”两层；只有当历史证据足够密集时才生成个性化技能，否则优先用 generic skill。
- 局限：评估依赖 LLM-based developer simulator；个性化收益小且不稳定；技能常提高执行强度而非执行效率。
- 阅读建议：高优先级。适合作为 skill mining、skill gating、skill evaluation 的实验模板。
- 证据来源：arXiv PDF 前 8 页和摘要。

### 4. GitSkills: A Dataset of Agent Skills on GitHub

- 问题背景：skill 已经成为 agent 扩展能力的一种轻量格式，但公开生态中 skill 文件如何写、如何复制、是否携带脚本、如何演化，目前缺少大规模数据。
- 核心方法：论文构建 GitSkills 数据集，抓取 GitHub 上的 SKILL.md 及相邻文件，按 content hash 去重，保留每个文件 occurrence 的仓库、路径、内容哈希、代表文件、front matter、正文、兄弟文件和提交历史。由于 GitHub code search 每个 query 最多返回 1,000 条，作者按文件大小递归切分搜索空间，直到每个范围可完整取回。
- 创新点：这是一个面向 agent skill 这种新软件工件的 mining software repositories 数据集。它把自然语言指令、脚本、引用文件和仓库元数据放在同一个结构化数据库里，能支持“哪些技能可复用、哪些技能危险、哪些技能只是 prompt”这类问题。
- 实验与 benchmark：数据集包含 3,797,117 个 SKILL.md 文件，来自 282,200 个公开仓库；按内容哈希聚合为 1,877,981 个 distinct contents。数据以 SQLite 发布，并提供 Hugging Face Parquet mirror 和 GitHub sample。论文定位为 MSR 数据集论文，重点是数据构造而不是模型 benchmark。
- 可迁移价值：可用于训练 skill retrieval、skill summarization、skill safety classification、技能依赖解析，以及从公共技能中学习工具使用流程。也能作为负样本来源，研究低质量或过度宽泛技能如何污染 agent 行为。
- 局限：只覆盖 GitHub 公共仓库；code search 不索引所有文件，作者也说明这是下界；代表文件不一定是原始来源。
- 阅读建议：建议加入 related work，尤其是任何关于 agent skills、prompt files、tool-use instruction mining 的工作。
- 证据来源：arXiv PDF 全 3 页和摘要。

### 5. Agentic Configuration Management (ACM): A Reference Configuration Model for Governed Agentic Systems

- 问题背景：现代 agentic systems 由 agents、prompts、tools、models、skills、subsystems、policies 和 workflows 构成，但 LangGraph、CrewAI、OpenAI Agents SDK 等框架的配置表达互不相同。现有 LLMOps/AgentOps 多关注 tracing、evaluation、observability，而不是跨框架、可审计、可重放的配置治理。
- 核心方法：ACM 借鉴传统 Software Configuration Management，把 agentic system 拆成 immutable configuration items、explicit baselines、lifecycle records、dependency-aware impact propagation 和 runtime provenance。它提供一个 framework-independent semantic representation，把不同框架的配置投影到统一配置图，再做验证、治理规则评估、重放式 runtime reconstruction 和影响传播。
- 创新点：它把传统 SCM 的版本、基线、依赖和审计概念移植到 agent 系统，而不是只做 prompt 版本管理。对复杂 agent 平台来说，关键是把“配置”和“运行时轨迹”分开治理，并能判断一次 prompt/tool/model/policy 变更会影响哪些能力和风险。
- 实验与 benchmark：PDF 前 8 页说明评估包含 qualitative governance scenarios、quantitative impact analysis、cross-framework projection experiments，目标是测试 semantic preservation、deterministic governance behavior 和 framework-independent operational consistency。摘要明确覆盖 LangGraph、CrewAI、OpenAI Agents SDK 三类框架。
- 可迁移价值：适合作为 agent 平台工程蓝图。可以把模型版本、工具 schema、技能版本、policy、workflow graph 都纳入 baseline，使后训练数据和线上 agent 实验具备可追溯配置。
- 局限：论文较长，前 8 页主要给模型和评估设计，具体量化结果需要继续读后文；当前结论应视为参考模型和工程框架，而不是大规模实证验证。
- 阅读建议：建议工程团队精读，研究团队可重点吸收配置图和影响传播语义。
- 证据来源：arXiv PDF 前 8 页和摘要。

### 6. EvoMem: Memory-Augmented Evolution for Code Optimization

- 问题背景：LLM-driven evolutionary program search 往往每次从头探索 mutation strategy，成功经验没有跨 run、跨 task 保存，导致重复试错和搜索成本浪费。
- 核心方法：EvoMem 增加 persistent memory。每次进化运行结束后，把成功 mutation events 抽取成带 provenance 的结构化、task-aware advice；下一次搜索时，根据当前任务和程序上下文检索少量相关 instruction，引导 mutation。直观地说，它把“哪些改法曾经有效”从一次性轨迹变成可检索的演化经验。
- 创新点：它把 memory 放进 evolutionary code search 的 variation 环节，而不是只做 RAG 式代码检索。对 Code Agent 后训练而言，成功/失败 mutation 可以形成带 reward 的程序编辑经验库。
- 实验与 benchmark：摘要和 PDF 前页显示评估覆盖 geometric optimization、multi-hop question answering、GPU kernel optimization 及相关 benchmarks；作者报告多数设置下 target metrics 或 search speed 有平均改进。由于前 8 页未完整展开所有表格，本日报不摘录未核实的具体数值。
- 可迁移价值：可用于构建 code-agent patch memory：存储“错误类型、代码上下文、尝试过的修复、验证结果、可迁移 advice”，在新 issue 上检索相似经验。
- 局限：需要确认 memory retrieval 是否会引入过时经验或错误泛化；具体 benchmark 数值需读后文表格。
- 阅读建议：建议精读方法和实验表，尤其关注 advice schema、检索粒度和负迁移控制。
- 证据来源：arXiv PDF 前 8 页和摘要。

### 7. Optimize Cheap, Deploy Strong: Cost-Aware Cross-Tier Transfer for Evolutionary Optimization

- 问题背景：演化优化 LLM prompts 和 agentic programs 的主要成本来自 fitness evaluation。每个候选都要让 answering LLM 跑验证集，如果一直用强模型，搜索成本高到难以扩展。
- 核心方法：论文把 LLM 在演化搜索中的角色拆开：高频 answering role 用便宜模型，低频 reflection/variation operator 用强模型，再利用 cross-tier transfer 把便宜层优化出的 prompt 或 agentic program 部署到强模型上。它不是简单换小模型，而是把“搜索成本”和“最终部署能力”解耦。
- 创新点：对 agentic post-training/RL 很有启发：昂贵模型不必承担所有 rollout，可以用 cheap tier 进行大规模探索，strong tier 负责少量生成、筛选或最终执行。这个思路适合构建低成本环境合成和工具使用轨迹优化。
- 实验与 benchmark：摘要指出任务是 LLM prompt 和 agentic program evolutionary optimization，例如 GEPA 类设置；评估关注 cheap-tier search、strong-tier deployment 的 upward transfer。前 8 页可确认研究问题和成本分解，但本次未核实全部数值结果。
- 可迁移价值：可以作为“廉价 rollout + 强模型反思 + 强模型部署”的训练管线原型，用于搜索 agent instructions、tool policies 或 verifier prompts。
- 局限：跨 tier transfer 可能依赖模型族相似性；便宜模型上的 fitness 排名不一定保留到强模型。
- 阅读建议：建议和 EvoMem 合并考虑：一个解决跨 run 记忆，一个解决跨模型成本。
- 证据来源：arXiv PDF 前 8 页和摘要。

### 8. CausalRepair: Bridging the Causality Gap in Large Language Model-Based Automated Program Repair via Dual-Slicing

- 问题背景：LLM-based APR 很依赖 repair context。测试上下文可能噪声大或不完整，静态分析给出的源代码上下文又可能包含大量未执行、非因果相关代码，导致模型修错位置或扩大修改范围。
- 核心方法：CausalRepair 提出 conversation-driven APR framework，以 minimal causal context 为核心。它用 dual-slicing 同时约束测试侧和源码侧上下文，让 LLM 更接近真正触发失败的因果路径，而不是把所有相邻代码都塞进 prompt。
- 创新点：它把“上下文选择”从相似度或调用邻近性推进到 causality-aware slicing。对 Code Agent 来说，这是非常关键的方向：修复循环应该围绕失败证据、执行路径、最小因果片段组织，而不是只依赖全文检索。
- 实验与 benchmark：摘要显示评估是 LLM-based automated program repair；候选摘要未给出具体 benchmark 名称和数值，本次 PDF 前 8 页未稳定抽取到足够表格信息，因此不编造具体数据集。日报只确认其问题设定和方法框架。
- 可迁移价值：可用于 agent 调试流程：失败测试 -> trace/slice -> minimal causal context -> patch -> rerun，形成更干净的训练轨迹和偏好比较。
- 局限：需要继续确认 dual-slicing 的实现细节、语言支持范围和 benchmark 表现；当前证据不足以判断泛化能力。
- 阅读建议：建议作为 APR context construction 的相关工作精读。
- 证据来源：候选摘要和 arXiv PDF 前 8 页抽取；具体 benchmark 未在本次可核实片段中确认。

## Search Agent

### 9. ENTLORE: A Graph-Grounded Benchmark for Latent Organizational Reasoning in Enterprise Question Answering

- 问题背景：企业 QA 不只是检索显式文档事实。很多问题依赖组织内部关系、项目归属、权限、层级、跨表结构等隐含关系，而这些关系可能没有直接写在公开文档里。现有 benchmark 往往把 answer path 显式写进语料，测的是 stated facts composition，不是 latent relation recovery。
- 核心方法：ENTLORE 先从 routine documents、authoritative organizational tables 和 operational records 重建 audited enterprise world，再构建 truth graph。发布给系统的是匿名化文档语料，而 gold relation 和 certification rules 保留在 benchmark 侧；问题被编译成 executable graph programs，用来计算 golden answers、proof dependencies、answerability 和 grounding status。
- 创新点：它把 benchmark 的真值层和系统可见证据层分开：系统必须从碎片化文档中恢复隐含组织关系，而 benchmark 用私有 truth graph 保证答案可验证。这比普通 RAG benchmark 更接近真实企业 search agent 的困难。
- 实验与 benchmark：ENTLORE 包含 2,341 documents、907 questions、1,153 entities 和 3,784 typed relations。评估矩阵覆盖 8 个模型和 7 种 access conditions。PDF 前 8 页显示 L1/L2/L3 分层，L3 是目标关系不出现在任何 released document 中的 latent-relation 问题；平均结果中 GraphRAG 在 L3 达到 36.2%，BM25 为 34.0%，LLM wiki 为 27.7%，Flat RAG 为 18.9%，agentic retrieval 为 13.5%，closed-book 几乎不能解决。
- 可迁移价值：适合构造 Search Agent 训练环境：让 agent 不只检索答案句，而要构建中间结构、做证据寻源、在证据不足时 abstain，并用 proof dependencies 评价轨迹。
- 局限：企业世界构造和匿名化成本高；agentic retrieval 表现较低说明简单“多轮搜”并不能自动获得结构推理能力。
- 阅读建议：高优先级。可作为企业 RAG/Search Agent benchmark 设计参考。
- 证据来源：arXiv PDF 前 8 页和摘要。

### 10. When Do Anchor-Based Pointwise LLM Rerankers Help? Retriever Quality, Statistical Scope, and Anchor Design

- 问题背景：LLM reranking 常见 listwise/pairwise/pointwise 三类。pointwise 成本低，但每个候选独立打分，缺少跨文档比较上下文。GCCP/PAGC 这类 anchor-based pointwise reranking 试图给每个候选同一个 query-focused anchor，恢复一部分 listwise 对比能力。
- 核心方法：论文不是提出新 reranker，而是 reproduction-first 地复现 GCCP/PAGC，然后系统测试边界条件：第一阶段 retriever 强弱、统计校正、anchor 构造方式、LLM backbone。核心发现是 contrastive scoring 有效，但复杂 aggregation 和 spectral MDS anchor 构造并非总是必要。
- 创新点：它的价值在实验严谨性。作者先从论文文本复现，发现缺少多个实现细节，补齐 8 个细节后才进入消融；再用 paired bootstrap 和 Holm-Bonferroni correction 重新审视显著性。这对 Search Agent 评测很重要，因为很多 reranking 改进可能只在弱 retriever 或未校正统计下成立。
- 实验与 benchmark：使用 TREC DL 2019/2020 和 8 个 BEIR subsets。PDF 前 8 页显示复现 TREC DL 的 mean absolute nDCG@10 gap 为 1.6%，BEIR 上 T5-XL 平均 gap 为 1.9%、T5-Large 为 4.5%。聚合策略在 22 个设置中只有 5 个显著有益，且一个数据集显著有害；在强 dense retriever E5 下，aggregation 在 8 个 BEIR 数据集中的 7 个统计上冗余。简单 top-k sentence anchor 在所有测试数据集上匹配或超过复杂 graph-partitioning anchor。
- 可迁移价值：Search Agent pipeline 不应盲目叠加复杂 reranking。建议先判断 base retriever 质量，再决定是否需要 anchor-based contrastive scoring；评测必须做多重比较校正和 reproduction audit。
- 局限：研究对象是一个代表性方法 GCCP/PAGC，结论不能直接泛化到所有 reranker；具体收益仍受数据集和 retriever 影响。
- 阅读建议：建议作为 reranking evaluation 的方法论论文阅读，尤其适合建立内部检索评测规范。
- 证据来源：arXiv PDF 前 8 页和摘要。

## General Agent 相关补充

- DuplexWorld 没进 Top 10，但值得后续关注：它提出 6 个 voice-agent worlds、11 类对话、156 个 scenarios、350+ 小时对话，并对 5 个商业系统做 3,825 次会话评估。PDF 结论显示即使最佳系统也未超过 Pass@1 0.490、turn-taking 0.653、DNSMOS 3.378。它对语音 agent 的工具调用、自然轮转和日常任务 benchmark 有价值。
- Comprendia 也值得跟进：它是 Eclipse plugin，把依赖图可视化、LLM code explanation、clone refactoring 和 CVE overlay 放在同一个图上，并用 Graph-Aware Callee Pruning 选择可审计上下文。它没进入 Top 10 是因为评估规模偏 demo，但“可见图结构作为 prompt relevance signal”很适合 code agent context selection。

## 今日重点趋势

1. Code Agent 研究正在从单次 issue 修复转向长期项目状态、技能生态、配置治理和跨 run 经验复用。
2. Search Agent 评测开始强调隐藏结构、可执行真值、proof dependencies 和统计可复现，而不是只看检索文本相似度。
3. 技能和配置文件正在成为新的软件工件，需要 mining、版本管理、质量评估和安全治理。
4. 成本感知训练越来越重要：cheap rollout、strong reflection、persistent memory、accepted consequence 都可以组合成更可扩展的 agentic post-training 管线。

## 潜在研究 idea

- 构建 “persistent repository world” 训练集：每个 episode 记录 path-scoped objective、tool calls、tests、review decision、accepted version delta，用于训练长程 Code Agent。
- 做 skill gating benchmark：比较 generic skill、personalized skill、retrieved public skill、no skill 在真实仓库任务上的收益与额外成本。
- 为 Search Agent 设计 latent-relation QA 环境：公开证据中不显式包含目标关系，benchmark 侧用私有 truth graph 验证答案和轨迹。
- 把 EvoMem 和 cost-aware evolution 结合：cheap tier 大规模探索修复/优化策略，成功 mutation 进入 memory，strong tier 只负责高价值反思和最终验证。

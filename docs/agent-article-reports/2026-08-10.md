## Code Agent

### 1. Agentic Planning for Symbolic Execution

- 链接：https://arxiv.org/abs/2608.06397
- 方向：Code Agent / Symbolic Execution / Tool-Use Planning
- 评分：4.800
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：符号执行可以系统探索程序路径，但实际运行经常被路径爆炸和资源预算卡住；单次 bounded symbolic execution 结束后，很多分支仍然没有覆盖。论文关注的不是替换符号执行器内部的状态选择算法，而是让一个 Agent 在多次有界运行之间学习“下一次该怎样配置、针对哪些代码区域继续跑”。

**核心方法**：Agolic 把底层符号执行器当成可调用工具。Agent 读取源代码、此前运行的覆盖率、replay 信息和失败的 targeting 尝试，随后选择下一轮 bounded symbolic execution 的配置；真正的路径搜索仍交给符号执行工具完成。这个设计相当于把 LLM 放在工具编排层，让它跨 run 积累证据、更新目标，而不是在一次工具调用里期待搜索器自动解决所有覆盖问题。

**创新点**：它把 Code Agent 的价值落在“如何使用现有程序分析工具”上。相比让模型直接写测试或猜 bug，Agolic 给出了一种更稳的闭环：观察覆盖缺口，形成下一轮分析目标，调用符号执行器，再用新覆盖反馈修正计划。

**实验与 benchmark**：论文在若干 C/C++ 程序上评估 branch-coverage exploration。PDF 前 8 页报告，Agolic 在每个程序上都超过连续符号执行，平均覆盖分支数超过其 3 倍；同时超过 coverage-guided fuzzing 和 compiler-based concolic execution 的单个语料库，并在 7 个程序中的 6 个达到比较语料都未覆盖的分支。

**可迁移价值**：适合借鉴到 Code Agent 后训练：把静态分析器、符号执行器、fuzzer、测试运行器包装为工具，让模型学习跨轮证据整合和预算分配。训练数据可以记录每轮工具配置、覆盖变化和失败定位。

**局限**：前 8 页能确认方法框架和核心结果，但具体 benchmark 程序列表、消融和提示模板需要继续读后文。

### 2. PyFlow: An Inter-procedural Static Analysis Framework for Python

- 链接：https://arxiv.org/abs/2608.07026
- 方向：Code Agent / Static Analysis / Python Security
- 评分：4.145
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：Python 的动态派发、一等函数、元编程、异常和属性查找机制让精确静态分析很难。对 Code Agent 来说，这类工具能力决定了自动审计、漏洞定位、补丁验证能否从“读文本猜测”升级到可解释的数据流证据。

**核心方法**：PyFlow 是一个面向 Python 的 IFDS-based interprocedural static-analysis 框架。它提供多阶段 IR pipeline、supergraph 构建、固定点迭代和 summary cache；分析开发者主要实现抽象域上的 dataflow semantics。论文实现了一个 taint analysis，用于评估框架是否能在 Python 安全分析中比现有 SAST 工具捕获更多跨过程数据流。

**创新点**：它不是一个单点规则扫描器，而是把 Python 分析抽象成可扩展的 IFDS 求解框架。对 Code Agent 的意义是，未来 Agent 可以调用更细粒度的“可解释 taint/path fact”工具，而不是只依赖 grep、测试和 LLM 代码阅读。

**实验与 benchmark**：摘要和前 8 页显示，PyFlow 与 DevSkim、Dlint、Bandit、Bearer、CodeQL、Pysa、Semgrep、Snyk 等 8 个 Python SAST 工具比较，使用来自一项 ICSE 2026 研究的 synthetic 与 real-world benchmarks。论文报告 PyFlow 在 synthetic benchmark 上取得最佳 aggregate recall 和 F1；在 real-world benchmark 上也取得最高 recall 和 F1，同时 precision 与 taint-based engines 竞争性相当。

**可迁移价值**：可作为 Code Agent 工具链候选：让 Agent 在修 Python 漏洞或审计依赖时调用跨过程 taint 分析，再把证据转化成补丁假设和回归测试。

**局限**：它本身不是 Agent 论文，主要贡献在程序分析框架；迁移价值取决于是否能暴露稳定 CLI/API、诊断格式和低误报工作流。

## Search Agent

### 3. DocMemo: Dynamic Evidence Discovery via Probabilistic Memory-Guided Retrieval for Multi-Modal Document Understanding

- 链接：https://arxiv.org/abs/2608.07067
- 方向：Search Agent / Long-Document Retrieval / Memory-Guided Reasoning
- 评分：4.395
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：长文档理解经常需要在数百页中找到稀疏且异构的证据。传统 single-round top-k 检索一开始就锁定页面集合，早期检索错了很难恢复；已有 iterative retrieval 虽然能多轮取证，但对跨轮状态如何传播、页面相关性如何动态变化刻画不足。

**核心方法**：DocMemo 把长文档推理建模为动态证据探索。系统维护三层记忆：Document Schema Memory 捕获文档结构先验，Page Belief Memory 维护页面相关性的动态估计，Question Episodic Memory 记录特定问题的推理轨迹。推理过程中，它用 Bayesian page belief updating、Thompson sampling、空间邻近传播和结构感知的自适应粒度访问来持续修正页面选择，并补充页面级证据中的细粒度视觉区域。

**创新点**：它把 Search Agent 的检索状态从静态 top-k 改成可更新的 belief memory。这个机制对深度研究类 Agent 很重要：检索不是一次性找资料，而是根据已读证据不断更新“下一页/下一段最可能有用”的概率。

**实验与 benchmark**：摘要和前 8 页报告，DocMemo 在 3 个 benchmark 上达到 state-of-the-art，并验证了 structured memory 与 dynamic page belief updating 的有效性。摘要未列出具体 benchmark 名称，前 8 页可确认主要实验关注长文档多模态理解。

**可迁移价值**：适合迁移到 Search Agent 的 long-context evidence loop：用结构记忆记录文档目录和版面，用 belief memory 管理候选证据优先级，用 episodic memory 避免重复查找和解释早期检索错误。

**局限**：今日只抽取前 8 页，具体 benchmark 名称、完整结果表和失败案例还需要读后文核验。

### 4. From Cheap Fakes to Pure Synthesis: Addressing the New Era of T2V Fake News Videos

- 链接：https://arxiv.org/abs/2608.06732
- 方向：Search Agent / Verification / Multimodal Evidence Reasoning
- 评分：3.850
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：T2V 模型让假新闻视频可以从零合成，检测器面对的不再只是把旧素材拼接成新叙事的 cheap fake。若生成视频与虚假叙事高度一致，检测模型容易掉进 modality alignment trap：看到文本和画面一致，就误以为可信。

**核心方法**：论文把 T2V-FNVD 定义为三分类任务：real、cheap fake、pure synthesis fake，并构建 PS-FNVD 数据集。数据集中既有 fabricated events with aligned deception，也有 true events with false visual provenance，避免模型只靠文本真假或视觉一致性走捷径。R-T2V 框架通过 conditioned rationale generation 和 supervised fine-tuning，把高层语义逻辑与低层生成痕迹结合起来预测真实性标签。

**创新点**：这篇不是通用 Agent 系统，但对 Search/Verification Agent 有启发：事实核查不能只问“文字与视频是否一致”，还要显式检查 provenance、生成痕迹和叙事类型。它把“证据一致但来源伪造”的情况做成任务标签。

**实验与 benchmark**：论文构建 PS-FNVD，并与 10 个 baseline 比较。摘要报告 R-T2V 达到 SOTA，相比第二名 accuracy 高 12.20 个百分点，macro F1 高 8.46 个百分点。

**可迁移价值**：可作为多模态搜索 Agent 的验证模块设计参考：在检索视频证据时分别判断事件真实性、视觉来源、生成痕迹和跨模态一致性。

**局限**：领域偏假新闻视频检测；对 General Agent 训练数据构造的直接价值有限。

## General Agent

### 5. Recipes for Creativity: Iterative Generation and Evaluation in Large Language Models

- 链接：https://arxiv.org/abs/2608.07243
- 方向：General Agent / Iterative Search / Evaluator Design
- 评分：3.750
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：生成模型常被评估为一次性产物，但人类创造通常包含反复生成、评估和修订。Agent 训练也有类似问题：如果只看最终输出，很难知道搜索过程和 evaluator 到底贡献了什么。

**核心方法**：论文把 FunSearch 思路迁移到 recipe generation：模型生成食谱候选，in-loop scorer 选择，再迭代产生下一批。实验变量包括 iteration count、generator temperature 和 selection-scorer model size，输出用基于 TTCT 的 LLM evaluation 与人类 benchmark 比较。

**创新点**：最有价值的结论是 evaluator design 可能比“多迭代几轮”更关键。对 Agent 系统来说，闭环搜索不等于无限迭代；选择器的偏好、能力和噪声会直接塑造搜索方向。

**实验与 benchmark**：论文围绕 2024 Pillsbury Bake-Off recipe generation 做两个实验。摘要报告，迭代生成-选择可以达到接近人类 benchmark 的创造力分数，但更多迭代本身不提升创造力；较小的 selection scorer 在多数 TTCT 维度上反而给出更高得分，temperature 主要影响 originality。

**可迁移价值**：可迁移到 Agent 任务合成：让 generator 和 evaluator 分离，系统性调 evaluator 尺度和选择准则，而不是只增加 self-refine 轮数。

**局限**：任务是创意食谱，不是工具环境；结论更像闭环搜索设计启发，不能直接当作 Agent benchmark 证据。

### 6. Can MLLMs Decode the Creative Leap? Introducing C4 for Cross-Concept Understanding

- 链接：https://arxiv.org/abs/2608.06501
- 方向：General Agent / Evaluation / Multimodal Reasoning
- 评分：3.725
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：MLLM 的创造性理解难评估，因为目标答案和奖励信号不像分类任务那样显式。跨概念理解要求模型从非显然但有意义的概念关系中恢复意图，这与 Agent 在陌生任务中解释隐含约束有一定相似性。

**核心方法**：C4 用中文成语视觉表达构造 Cross-Concept Creativity 评测。编码侧把目标 slot 映射到可图像化的替代概念，并通过人工标注和第三方审核的 cross-concept network 生成 bridge paths；解码侧要求模型恢复目标含义。C4-Eval 包含 184 个 synthetic items 和 37 个人类创作图，共形成 884 个 primary answer-recovery cases。

**创新点**：它把“创意理解”拆成可控的 bridge count、depth 和 exact-answer recovery，而不是只让评委主观打分。这对 Agent 评测的启发是，可以把隐含规则理解做成带结构路径和难度索引的数据。

**实验与 benchmark**：论文评估 10 个 MLLM。摘要报告最强闭源模型 primary accuracy 为 50.7% 和 48.0%，开源模型明显更低；candidate constraints 明显提升准确率，而 bridge hints 和 explanation requests 只带来有限收益。

**可迁移价值**：可用于构造 Agent 隐含约束/规则迁移测试：不只评估答案，还记录概念桥、干扰项和提示条件变化。

**局限**：与工具调用、搜索或代码执行没有直接关系，因此排序低于 Agolic、DocMemo 和 PyFlow。

### 7. LyEvO: Lyapunov-Guided Evolutionary Optimization for Safe and Robust Sim-to-Real Policy Learning

- 链接：https://arxiv.org/abs/2608.06481
- 方向：General Agent / Policy Optimization / Verification Loop
- 评分：3.685
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：从仿真到真实部署的控制策略需要安全、鲁棒且可评估。虽然机器人控制不是当前关注重点，但论文里的“优化-验证-扩大可部署区域”闭环，对 Agent 在工具环境中做安全策略训练有方法启发。

**核心方法**：LyEvO 结合 constrained Evolutionary Optimization、Statistical Model Checking 和 Lyapunov stability analysis。系统先用动力学先验计算初始稳定区域，再从该区域采样 operational scenarios，联合优化并统计验证 policy；如果验证通过，就基于结果扩大区域边界。

**创新点**：它把 policy learning 与 deployment readiness criterion 绑在一起：不是只追求平均 reward，而是用可验证区域逐步扩张来控制风险。

**实验与 benchmark**：摘要报告在 Cartpole 和 3D Quadrotor benchmarks 上做大量仿真和定向真实实验，展示安全鲁棒的 sim-to-real transfer。

**可迁移价值**：可借鉴为 Agent 沙盒课程学习：从已验证安全任务区域开始，训练后用统计检查扩展任务分布，避免直接把模型推到不可控工具空间。

**局限**：机器人控制领域较远，方法迁移需要重新定义 Agent 环境中的稳定性或安全区域。

### 8. MMAG: A Multi-Control Mixed Audio Generation Benchmark

- 链接：https://arxiv.org/abs/2608.06900
- 方向：General Agent / Benchmark Design / Multi-Control Evaluation
- 评分：3.500
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：复杂生成系统需要同时满足语义、身份、时间和质量约束。虽然 MMAG 是音频生成 benchmark，但它评估“多控制条件交互能力”的协议，对 Agent benchmark 设计有可迁移价值。

**核心方法**：MMAG 包含约 4,000 个人工验证音频片段，标注覆盖 speech content、speaker identity、music attributes、sound events 和 temporal relationships，并包含 voice cloning 与 timestamp-conditioned generation 子集。评估协议同时衡量 acoustic fidelity、speech quality、semantic alignment 和 temporal accuracy。

**创新点**：它强调 benchmark 不能只测单一维度，否则模型可能在某项指标上好看但整体控制失败。论文还比较了 agentic orchestrators、unified audio-visual generation models 和 native mixed-audio generators，揭示不同架构的取舍。

**实验与 benchmark**：摘要报告，代表性系统在不同能力间存在明显 trade-off，没有模型稳定全面领先。

**可迁移价值**：可迁移到 Agent 评测：把任务拆成目标完成、工具成本、时间顺序、证据一致性和用户约束多个可审计维度，而不是只用单一 success rate。

**局限**：音频领域特化明显，对 Agent 后训练的直接可操作性有限。

### 9. MI-MIDI: Mechanistic Interpretability of Text-to-MIDI Generation Models via Probing, Lenses and Steering

- 链接：https://arxiv.org/abs/2608.06638
- 方向：General Agent / Mechanistic Interpretability / Steering
- 评分：3.395
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：可解释性研究多集中在文本或音频模型，符号音乐生成模型较少被系统分析。对 Agent 研究的间接意义在于，它展示了如何用 probing、lens、activation patching 和 steering 检查模型内部是否形成可控概念。

**核心方法**：论文分析 text2midi 和 MIDI-LLM 两类 text-to-MIDI 系统，使用 linear probing、logit/tuned lenses、activation patching 和 difference-in-means steering。它检查 pitch、instrumentation、harmony、texture 等音乐概念是否线性可解码，以及不同架构在深度层中如何形成和转向音乐词表。

**创新点**：它不仅观察概念可解码，还通过 steering 做双向控制，并比较 all-layer interventions 在两类架构上的鲁棒性差异。

**实验与 benchmark**：摘要报告，两个模型中都能恢复有音乐意义的结构；text2midi 跨层逐步细化预测，MIDI-LLM 则在继承的文本基底中工作，后期快速旋转到音乐词表。steering 可以双向改变 register 和 polyphony，并在 MIDI-LLM 中影响 tempo/energy。

**可迁移价值**：可启发 Agent 内部状态诊断：用 probing/patching 检查模型是否真的表示了任务状态、工具意图或错误类型，再设计轻量 steering 修正行为。

**局限**：领域远离 Agent；今日只作为可解释性工具箱线索保留。

### 10. Beyond Call and Response: Modelling Reciprocal Coordination in Human-AI Vocal Ensembles

- 链接：https://arxiv.org/abs/2608.07376
- 方向：General Agent / Multi-Agent Coordination / Research Architecture
- 评分：3.230
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：很多人机音乐系统是 call-and-response：人类表演，系统解释并回应。但无指挥 vocal ensemble 中，多个歌手同时行动并相互影响，集体状态来自多对多的连续调节。

**核心方法**：论文把 vocal ensemble 建模为 coupled dynamic systems，并提出一个 vocal agents 研究架构：从现场 multichannel capture，到方言/歌唱感知表征、collective-state inference、vocal generation 和 in-situ evaluation。它特别把非等时节奏曲目作为难例，因为这类曲目不能简化为 beat grid。

**创新点**：它强调 Agent 不只是响应人类动作，而是进入并改变集体状态。对 General Agent 来说，这是多智能体协调和人机共适应的一个清晰问题表述。

**实验与 benchmark**：摘要和前 8 页更偏 research agenda，未看到传统量化 benchmark 或大规模实验结果。

**可迁移价值**：可作为多 Agent 协调研究的概念参考：评估一个 Agent 是否同步，还要看它如何改变群体中的领导、风格和传承结构。

**局限**：不是完整工程系统或训练方法，证据主要是架构与研究议程，实证强度弱。

## 值得关注但未进 Top 10

- SemBridge: Semantic Token Anchoring for Continuous-Latent Autoregressive Speech Generation。训练时用离散语义 token 监督连续 latent autoregressive speech generation，启发是“训练期引入显式语义锚，推理期保持连续表示”；但音频领域较远。
- Multi Codec Discrete Diffusion Model for Text Guided Speech Inpainting and Editing。HiCoDD 按 RVQ 层级逐级扩散，适合思考分层 token 生成与局部编辑；但与 Agent 工具闭环关系较弱。
- Cloud-Boosted Low-Compute Multi-Channel Speech Enhancement。边端模型借助服务端 delayed output、layerwise feature boosting 和协同 beamforming，可类比边端 Agent 调云端 teacher，但任务本身偏语音增强。
- Objects as Audio-Visual Modal Sound Fields。用 3D Gaussian Splatting 与 modal parameters 建模物体声场，对具身交互表征有远期启发，当前不适合作为 Agent 主线。

## 今日重点趋势

1. Code Agent 的工具使用开始从“直接生成代码”转向“规划现有程序分析工具的多轮调用”。Agolic 是今天最直接的例子。
2. Search Agent 的证据检索正在从静态 top-k 走向跨轮记忆和概率化 belief 更新。DocMemo 的三层记忆结构值得重点拆解。
3. 今日 arXiv 候选整体偏多模态、音频和评测，真正强相关 Agent 论文数量有限；排序时没有因为出现 language model、agentic orchestrator 等词就给高分。
4. 可迁移方法集中在闭环：生成-评估、优化-验证、检索-更新、分析-再规划，这些都能抽象成 Agent 后训练轨迹。

## 潜在研究 idea

- 为 Code Agent 构造“工具预算规划”训练集：给定代码、覆盖报告和前几轮符号执行结果，让模型选择下一轮分析目标和参数。
- 把 DocMemo 的 Page Belief Memory 改造成网页/仓库级 Evidence Belief Memory：每次搜索、打开文件或运行测试后更新证据优先级。
- 将 PyFlow 一类静态分析器接入自动修复 loop：用 taint fact 生成补丁假设，再用测试和动态检查验证。
- 在 Agent benchmark 中引入多维控制评分，避免模型只优化最终 success rate 而牺牲引用可信度、工具成本或约束满足。

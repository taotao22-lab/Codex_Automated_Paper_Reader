## General Agent

### 1. DarwinX: Evolving Agent Harnesses Through Natural Selection

- 链接：https://arxiv.org/abs/2608.07545
- 方向：General Agent / Harness Evolution / Tool-Use Self-Improvement
- 评分：4.925
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：论文把 Agent 能力拆成两部分：冻结的底座模型，以及围绕模型运行的 harness，包括提示词、工具、技能、控制流和记忆。很多 self-improvement 系统已经允许 Agent 改自己的 prompt 或流程，但通常是单线继承：当前版本稍微变好就替换旧版本。这个机制容易陷入局部最优，也容易在某些任务变好时让其他任务回退。

**核心方法**：DarwinX 把 harness 改写变成“种群选择”。系统保留多个 lineage，用 preserve-and-extend contract 只接纳能扩展覆盖且不回退的变体；archive 允许不同分支后续重组；失败案例、教师建议和自生成证据都进入同一个 edit interface。适应度不靠人工挑选答案，而是直接使用 benchmark 自带 verifier。直观地说，它不是让模型一次性想出更好的 Agent，而是把评测计算转化成可复用的 harness 资产。

**创新点**：这篇非常贴合 General Agent 后训练，因为它演化的是工具使用和控制流程，而不是模型权重。相对 DGM/SICA 类自改代码路线，DarwinX 强调“多 lineage + 不回退约束 + 跨 benchmark verifier”，更像一个稳定的 agentic post-training 外环。

**实验与 benchmark**：PDF 前 8 页报告，DarwinX 在四类逐步拉开训练信号与测试分布的 benchmark 上平均提升约 17 个点。Terminal-Bench 2.1 在 matched base 上提升 7.7 点到 83.2%，强底座达到 84.7%；TerminalWorld held-out split 达到 68.3%；WebArena-Infinity real-task pass@1 从 43.5% 提升到 93.0%；Terminal-Bench 2.1 演化出的 harness 还能不改动迁移到 SWE-bench Verified。

**可迁移价值**：很适合作为你的 Agent 训练框架参考：把 prompt、工具 schema、技能文档、错误恢复策略都视为可演化对象；用 benchmark verifier 产生奖励；用 archive 保留专长分支；用不回退约束保护已有能力。

**局限**：前 8 页能确认主结果和框架，但更细的 harness diff、失败类型和 archive 操作细节需要读后文与代码。

### 2. RouteGuard: Certifying Routing Gain in LLM Multi-Agent Systems When Complementarity Is Not Enough

- 链接：https://arxiv.org/abs/2608.07583
- 方向：General Agent / Multi-Agent Routing / Deployment Certification
- 评分：4.030
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：多 Agent 系统常见做法是把不同模型或专家当作 advisor，再训练一个 router 选择谁回答。问题是，advisor 之间“看起来互补”不等于线上一定有收益；router AUC 高也不保证部署后会超过最强单模型。

**核心方法**：RouteGuard 给出 routing gain 的部署前认证框架。论文把收益分解为 activity 与 conditional gain，并指出真正限制可部署收益的是 conditional-regret functional，而不是传统 gate AUC。它提供有限样本 certification bracket 和对应下界，用来判断“这个路由系统是否有足够证据值得上线”。

**创新点**：它把 Multi-Agent 从经验调参问题拉回统计认证问题。对实际 Agent 系统有用的是 guardrail 思路：上线前先判断路由收益是不是只来自少数 workload cell，而不是平均指标偶然好看。

**实验与 benchmark**：论文在 RouterBench 和 OpenRCA 上验证。RouterBench 包含 11 个跨家族模型，prompt-level sampling 下可认证超过 GPT-4，但 workload-cluster resampling 下不予认证，因为收益集中在 86 个 workload cell 中的 3 个。OpenRCA 的三个 Gemini advisor 被判断为统计冗余，协议拒绝认证。半合成预注册控制实验显示，样本量达到阈值时能认证真实收益，对真 null 不认证。

**可迁移价值**：适合作为 Agent ensemble/router 的上线前检查模块：不仅评估平均 pass rate，还按 workload cluster 检查收益是否稳健，避免把少数任务上的偶然互补当成通用能力。

**局限**：它不直接提供训练方法，主要贡献是认证与统计决策；工程落地需要先定义稳定的 workload cell 和采样单元。

### 3. SR-OPSD: Self-Referenced On-Policy Self-Distillation

- 链接：https://arxiv.org/abs/2608.09745
- 方向：General Agent / Post-Training / Token-Level Distillation
- 评分：3.945
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：On-policy self-distillation 可以把稀疏反馈变成 token 级监督，但 teacher 通常是 stop-gradient 或 EMA 版本，并且会随 student 与上下文分布一起移动。直接追逐这个移动目标，可能造成训练不稳定或分布过度集中。

**核心方法**：SR-OPSD 用 self-referenced 形式重新定义 token-level distillation target：在固定 student-generated context 下，目标是 self-teacher 与 reference policy 的几何插值；同时用 Rényi divergence family 调节投影几何。这样把“目标放在哪里”和“student 如何向目标投影”拆开，插值系数控制 teacher/reference 的混合，Rényi 阶数控制对 token density ratio 的敏感度。

**创新点**：对 Agent 后训练的启发在于，它提供了一种介于 SFT 与 RL 之间的稠密监督方式。对于代码执行、工具调用轨迹或搜索轨迹，如果只有最终成败奖励，可以把成功轨迹或带额外上下文的 teacher 策略蒸馏回当前策略，同时用 reference 约束防止策略塌缩。

**实验与 benchmark**：PDF 前 8 页显示实验覆盖科学问答、数学推理和代码生成。科学问答使用 SciKnowEval L3 reasoning subset，报告 Avg@16、Maj@16、Best@16；训练框架使用 verl，模型包括 Qwen3-8B 与 OLMo-3-7B-Instruct。摘要称 SR-OPSD 在多个任务和模型上达到 SOTA，并优于 SDPO、on-policy GRPO、GRPO 等基线。

**可迁移价值**：可迁移到 agentic post-training：把执行反馈转成 token 级偏好目标，让模型学习“为什么这一步工具调用/查询/修复更好”，而不是只在 episode 末端给奖励。

**局限**：前 8 页能确认公式和部分实验设置，但代码任务的具体 benchmark、数值表和失败模式需要继续核验。

### 4. DSLE: A Learning Environment for Dark Souls Boss Encounters

- 链接：https://arxiv.org/abs/2608.09902
- 方向：General Agent / Embodied Benchmark / Sparse-Reward Environment
- 评分：3.870
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：很多 Agent benchmark 还停留在离散文本、网页或短 horizon 任务。DSLE 提供的是实时、高维视觉输入、稀疏终局奖励、动作真正作用于运行中游戏的环境，用来测试长程控制和失败恢复。

**核心方法**：论文把 Dark Souls: Remastered 的 22 个 boss encounter 封装成 Gymnasium-style 接口，并定义 DSLE-5 作为起步套件，覆盖近战、狭窄场地、环境 hazard、多目标和高速 final-boss fight。每个 step 都是对游戏实例执行真实动作，而不是模拟器里的简化状态转移。

**创新点**：它的价值不是 LLM tool-use，而是环境难度设计：真实时间压力、稀疏奖励和多阶段战斗让现有视觉 RL baseline 明显失败。这类环境可以提醒我们，Agent benchmark 需要能暴露长期规划、状态估计和失败恢复，而不是只测一次性问答。

**实验与 benchmark**：DSLE-5 上比较 random policy、expert system、evolutionary baseline、PPO、DQN。expert system 与 evolutionary baseline 只能在 tutorial boss Asylum Demon 上达到 63% 与 43% peak win rate；其他四个 DSLE-5 boss 无方法打赢。PPO/DQN 在 tutorial boss 上不超过 0.33%，其余为 0%。论文还扩展到 22 个 encounter，即使给 level-50 属性，evolutionary baseline 也只打赢少数早期 boss。

**可迁移价值**：可作为 General Agent 环境合成的反例库：好的环境应有真实执行反馈、非平凡状态估计、长程失败恢复和可复现实验接口。

**局限**：游戏控制与 LLM 工具使用差距大；对你的主要方向属于 benchmark 设计启发，不是直接训练数据方案。

## Search Agent

### 5. BOUND: Brief-Guided Corrective Preference Distillation at Search-Control Boundaries

- 链接：https://arxiv.org/abs/2608.08768
- 方向：Search Agent / Preference Distillation / Search Drift
- 评分：4.695
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：深度搜索 Agent 需要多轮查询、检索和推理。局部相关证据很容易把 Agent 带偏：它可能围绕错误 anchor 继续搜索，或者逐渐忘记原问题约束。传统 trajectory SFT、outcome supervision 或 step supervision 很少明确区分“任务对齐的下一步”和“局部看似合理但会加剧漂移的下一步”。

**核心方法**：BOUND 在 student 产生的 decision-time state 上构造 teacher-side search-state brief。这个 brief 保留原始搜索目标与关键约束，同时总结已确认的证据、缺失信息和漂移状态。Teacher 根据 brief 判断 student continuation 是否包含可纠正的 search-control 错误；再结合 rollout outcome，构造两类偏好对：纠偏 continuation 对原 continuation，或 supported answer 对不必要的继续检索。最后用 DPO 把这些 state-matched preference pair 蒸馏到 student，brief 只在训练阶段使用。

**创新点**：它把 Search Agent 的训练信号落在“搜索控制边界”上。不是简单奖励最终答对，而是定位哪一步开始应该纠偏或停止。这正好对应搜索轨迹后训练里最难的数据标注问题。

**实验与 benchmark**：论文在 4 个 multi-hop QA benchmark 和 3 个 deep-search benchmark 上评估。PDF 前 8 页报告，在重新跑 baseline 的 6 个 benchmark 中，BOUND 在 5 个数据集和 14 个指标中的 12 个领先；在同一 search-control interface 下，相比 Trajectory SFT，Bamboogle 提升 5.6 EM，BrowseComp-Plus 提升 4.8 accuracy。

**可迁移价值**：非常适合用来构造 Search Agent 训练数据：保存查询轨迹、证据状态、漂移诊断和可纠正动作，把“何时换查询、何时停止、何时回到原约束”变成偏好学习样本。

**局限**：前 8 页尚未完整覆盖所有 benchmark 细节和 teacher prompt；实际复现需要看数据构造与验证过滤规则。

### 6. What Would Fix This RAG Failure? Auditing Counterfactual Response with Paired Evidence Interventions

- 链接：https://arxiv.org/abs/2608.08944
- 方向：Search Agent / RAG Failure Audit / Evidence Intervention
- 评分：4.305
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：RAG 系统答错时，单条失败轨迹不能告诉我们“如果补上缺失证据会不会修好”或“如果删掉无关证据会不会修好”。因此，很多失败分析会把检索错误、阅读器错误和证据污染混在一起。

**核心方法**：Pair-ID 是一个 offline audit。它固定 query、retrieval state 和 reader，然后交叉执行两种证据干预：添加 missing support、删除 verified nonsupport。这样能得到同一失败在不同修复条件下的 counterfactual response vector。论文还使用 SHA-256 固定抽样顺序，避免先看结果再挑样本。

**创新点**：它不是又做一个 RAG 修复器，而是提供了“失败可修复性”的诊断协议。对 Search Agent 来说，这能把训练信号拆成：需要补证据、需要删噪声、还是 reader 本身不稳定。

**实验与 benchmark**：论文从 19,981 个 benchmark query 中识别 11,105 个 eligible Qwen failures，再固定抽样 1,200 个。1,190 个有效再生成失败中，support addition 修复 197/600 个 JOINT cases，比例 0.328，95% CI 为 [0.292, 0.367]；deletion 修复 162/1,190，比例 0.136，[0.117, 0.155]。原始视图对 response cell 有部分预测力，macro AUROC 0.678，但 exact-vector accuracy 0.637 没超过 majority-vector baseline 0.646。

**可迁移价值**：可以作为搜索轨迹数据清洗工具：对失败样本做 paired evidence intervention，把“检索不足”和“证据噪声”分开标注，再训练 Agent 选择下一步检索或清洗动作。

**局限**：它明确声明是 frame-scoped offline response audit，不是 runtime repair policy；不能直接当作在线修复算法。

### 7. Difficulty-Gated Fusion of Reasoning Views for Temporal Retrieval

- 链接：https://arxiv.org/abs/2608.08940
- 方向：Search Agent / Temporal Retrieval / Query Reformulation Fusion
- 评分：3.925
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：时间推理检索经常不是靠关键词重合，而是要理解查询背后的时间关系。把 query 改写成多个 temporal reasoning view 可以提高覆盖，但如果所有 view 等权融合，会把不可靠改写也混进最终排序。

**核心方法**：论文提出 query-difficulty-gated fusion。每个 reasoning view 会产生一个分数分布签名，包含 softmax entropy、score gap、dispersion 等 8 维 query-performance-prediction 特征；一个约千参数的小 gate 根据这些签名为每个 query 分配 view 权重。推理时不需要 relevance label、不重排、不微调 retriever。

**创新点**：这篇给 Search Agent 一个很实用的模块化思路：多查询规划之后，不要默认每个查询同等可信，而是用检索分布本身估计“哪个查询视角更可能靠谱”。这比让 LLM 事后解释每个 view 更便宜。

**实验与 benchmark**：论文在 Tempo benchmark 上评估 6 个 retriever，从 BERT encoder 到 7B decoder retriever 都有提升，弱 backbone 收益最大。最强 retriever 达到 0.297 和 0.303 nDCG@10；相对原始 query 的 per-query gain 在 paired bootstrap 下显著，p < 0.001。per-query oracle 达到 0.364，说明 view selection 仍有明显上限空间。

**可迁移价值**：可直接用于 Search Agent 查询规划：生成多个查询视角后，用轻量 gate 根据各视角检索分布动态加权，减少错误 reformulation 的污染。

**局限**：当前只验证 temporal retrieval；是否能迁移到网页搜索、科学文献搜索和代码搜索，需要重新定义 view signature 与训练任务。

## Code Agent

### 8. P3: Joint Program-and-Proof Planning for Verified Code Generation

- 链接：https://arxiv.org/abs/2608.09277
- 方向：Code Agent / Verified Code Generation / Lean
- 评分：4.515
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：验证式代码生成要求 LLM 同时生成可执行程序和机器可检查证明。常见流程先写程序再补证明，但程序如果没有提前考虑证明结构，后续很容易陷入修代码、修证明的脆弱循环。

**核心方法**：P3 先从形式化规格中生成统一的 program-and-proof plan，再在共享计划下展开实现和证明 scaffold。它借鉴 Dijkstra 的观点：程序和正确性论证应该一起设计。论文还提出 Lean4Commit0，从真实软件仓库抽取核心 API，并把 API 间关系规格翻译成 Lean 任务。

**创新点**：对 Code Agent 的关键启发是“先联合规划证明义务，再写代码”。这比直接让模型 trial-and-error 修 Lean proof 更接近可验证开发流程，也能减少工具调用闭环中的无效修补。

**实验与 benchmark**：论文使用 4 个 frontier LLM backend，在 Verina、AlgoVeri 和 Lean4Commit0 上评估。摘要报告 P3 在每个 benchmark-model setting 中 solve rate 最高；相对强 baseline 提升 4.6 到 11.2 个百分点，并在困难子集上最多降低约 40% API cost 和约 37% wall-clock time。消融显示，相比 implementation-only planning，联合 program-proof planning 仍有 3.3 到 8.3 点收益。

**可迁移价值**：可迁移到 Code Agent 的规划器：在写补丁前显式列出测试、类型约束、不变量和证明/验证义务，再让实现与验证 scaffold 同步生成。

**局限**：Lean 任务和普通软件仓库 issue resolution 之间仍有距离；需要读后文确认 Lean4Commit0 的任务覆盖和仓库抽样方式。

### 9. SimP: Unifying Syntax- and Semantic-Guided Techniques for Efficient Program Reduction

- 链接：https://arxiv.org/abs/2608.08352
- 方向：Code Agent / Debugging / Program Reduction
- 评分：4.210
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：编译器 bug 的触发程序往往很大，开发者需要 program reduction 把它缩到便于定位的最小形式。传统 reducer 多依赖语法规则反复删除片段并测试 bug 是否保留，前期有效，但后期会进入长尾：大量候选变换要么语法不合法，要么不再触发 bug。

**核心方法**：SimP 先使用现有 rule-based reducer 快速删掉明显无关代码；当检测到长尾后，切换到 LLM + rule-based 的 hybrid mode。LLM 通过定制 prompt 做语法和语义引导，提出更有可能保留 bug 行为的规约方向，规则 reducer 继续承担验证与机械变换。

**创新点**：它没有让 LLM 独自“理解并重写最小程序”，而是在长尾阶段把 LLM 用作语义剪枝器。这种工具组合很适合 Code Agent：把昂贵模型调用集中在传统工具效率下降的位置。

**实验与 benchmark**：PDF 前 8 页报告，代表性 reducer LPR 在公开 benchmark 上超过 80% case 需要 1 小时以上，超过 25% 需要 7 小时以上；SimP 的目标是在保持 reduction size 相近的同时显著减少时间。摘要说明 SimP 提高 reduction efficiency，且 LLM 金钱成本可忽略。

**可迁移价值**：适合纳入自动调试 Agent：当测试失败样例过大时，先用传统 reducer；进入长尾后调用 LLM 提出语义保留的删减策略，再用编译器/测试器验证。

**局限**：前 8 页尚未覆盖完整结果表；需要继续核对不同语言/编译器上的泛化性和 LLM 调用次数。

### 10. MOSAIC: Adversarial Co-evolution of Specialist Heuristics and Problem Instances for LLM-based Automated Heuristic Design

- 链接：https://arxiv.org/abs/2608.07544
- 方向：Agent Training Data / Environment Synthesis / Automated Heuristic Design
- 评分：4.140
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：LLM 自动启发式设计通常在固定小数据集上优化平均表现，用 scalar better/worse feedback 或 verbal gradient 指导搜索。但组合优化问题没有单一启发式能覆盖所有实例分布；单个标量也很难告诉模型“在哪类实例上为什么失败”。

**核心方法**：MOSAIC 在 Quality-Diversity archive 中共同进化问题实例和 specialist heuristic。Archive 按结构化实例特征分格，每个 cell 保存 specialist heuristic、代表性实例和解释性 insight。实例负责暴露当前 heuristic 的弱点，heuristic 再针对新暴露区域进化。对于来自远距离 grid region 的 heuristic pair，LLM-guided evolutionary loop 生成 discriminative instances，decision tree 找出谁在哪些 feature-space region 获胜，reflection LLM 再生成可持久化 insight 指导交叉和变异。

**创新点**：它把“训练任务”和“求解策略”一起进化。对 Agent 训练数据构造尤其有价值：我们也可以让环境/任务专门暴露当前 Agent 的弱点，再让策略或 harness 针对这些区域补齐能力。

**实验与 benchmark**：摘要和前 8 页显示，MOSAIC 在多个组合优化问题、测试规模和 LLM backbone 上，与 FunSearch、EoH、ReEvo、HSEvo、MCTS-AHD、PathWise、EoH-S 等 LLM-based AHD 方法比较。论文报告 portfolio consistently outperforms state-of-the-art LLM-based AHD methods；共同进化实例在 feature-space coverage 和 heuristic discrimination 上也优于 evolutionary instance-generation baseline。

**可迁移价值**：可以借鉴成 AgentWorld/EnvFactory 类系统的任务生成策略：archive 中保留失败区域、代表任务和修复 insight，持续生成能区分 harness/策略能力的新任务。

**局限**：领域是组合优化启发式，不是通用工具 Agent；具体数值表和 COP 任务细节需要读后文确认。

## 值得继续跟进但未进 Top 10

- Guardian Crawler: Retrieval-First Knowledge Discovery with Bounded LLM Augmentation for Noisy Web Intelligence。它提供检索优先、受限 LLM 生成和引用检查的合成 web-like testbed，但实验只有 synthetic 900-document corpus 和 10 queries，作者也明确不主张统计显著优越或迁移到 live web。
- LLM-Based Embeddings for Program Analysis and Optimization。它用 LLMCompiler 的 source/IR embedding 做算法分类和异构设备映射，报告 algorithm classification error rate 1.54%，比 SOTA 改善 12%；对 Code Agent 工具表征有启发，但不是 agentic workflow。

## 今日重点趋势

1. Agent 能力正在被拆到 harness、router、query planner、evidence auditor、program reducer 等外部结构中，而不是只靠更强底座模型。
2. 搜索类论文开始关注“什么时候继续搜、什么时候纠偏、什么时候删噪声”，这比单步 RAG 排序更接近 Search Agent 训练需要。
3. Code Agent 方向的高价值信号来自可验证闭环：程序-证明联合规划、传统工具与 LLM 的长尾协作、以及把执行/证明反馈变成训练数据。
4. 环境合成和任务进化值得重点关注。DarwinX 与 MOSAIC 都说明，能力增长可以来自持续生成能暴露弱点的任务，并把成功修复保存为可复用资产。

## 潜在研究 idea

- 做一个 Agent harness archive：每个 harness 记录适用任务簇、失败簇、工具配置和 verifier 结果，接受新变体前必须通过不回退测试。
- 为 Search Agent 构造 drift-boundary 偏好数据：在真实搜索轨迹中标注错误 anchor、约束漂移、无必要继续检索，并训练模型在边界处纠偏或停止。
- 把 Pair-ID 式证据干预加入 RAG 评测流水线：对失败样本系统性添加支持证据、删除无关证据，区分检索不足、噪声污染和 reader 缺陷。
- 在 Code Agent 中加入 reduction tool loop：失败样例过大时自动调用 reducer，长尾阶段让 LLM 提议语义保留变换，再由测试/编译器验证。
- 用 MOSAIC 式 archive 合成 Agent 训练环境：让任务生成器主动寻找当前 agent policy 的薄弱区域，而不是随机采样静态 benchmark。

## General Agent

### 1. CalibForge: Adversarial Solver Calibration for Scaling Learnable Terminal Tasks

- 链接：https://arxiv.org/abs/2608.06352
- 方向：General Agent / Terminal Agent / Training Data Synthesis
- 评分：4.930
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：训练 terminal agents 需要可执行、可验证、难度合适的任务。只验证任务“能不能跑通”不够，因为过易任务不能提供有效学习信号，过难任务又会让 solver 一直失败，难以形成稳定监督。

**核心方法**：CalibForge 把任务合成过程改成 solver-relative calibration。系统先生成候选 terminal task，再让不同能力或不同设置的 solver 实际尝试，依据验证过的行为反过来修订任务。论文强调两类校准：multi-solver calibration 追求异构 solver 之间的分歧，contrastive solver calibration 追求强 solver 能过、弱 solver 不能过的关系。这样任务不只是“可执行”，而是落在某个 solver 池的 learnable zone。

**创新点**：它把 Agent 训练数据构造从静态 authoring 推进到“用 solver 行为校准数据难度”。这对 post-training 很直接：任务筛选标准可以不再是人工标签或单 solver pass/fail，而是多 solver 分歧、强弱关系和可验证执行轨迹。

**实验与 benchmark**：论文构造了 5,431 个 calibrated terminal tasks。摘要和前 8 页报告，使用完整集合训练的模型在 Terminal-Bench 2.0 上达到 32.58% 和 47.57%；相对对应 base model，最大提升为 Terminal-Bench 2.0 上 24.71 个百分点、SWE-bench Pro 上 27.68 个百分点、Doc2Repo 上 30.04 个百分点。

**可迁移价值**：可直接借鉴到 Agent 数据管线：先生成任务，再用多个 solver 执行校准，把“可学但不平凡”的任务留下；也可以把强弱 solver 的差异作为 reward shaping 或课程学习信号。

**局限**：前 8 页能确认系统目标、校准机制和主要结果，但更细的任务类型分布、失败样例和长尾任务质量需要读后文与附录。

### 2. EnvACE: Internalizing Environment Dynamics via World Rehearsal for Agentic Reinforcement Learning

- 链接：https://arxiv.org/abs/2608.06197
- 方向：General Agent / Agentic RL / World Rehearsal
- 评分：4.885
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：长程工具使用 Agent 的 RL 通常依赖真实或合成可执行环境。真实环境交互贵，合成环境验证也贵；外部 simulator 又容易和真实工具反馈脱节。训练成本和环境可扩展性成为瓶颈。

**核心方法**：EnvACE 用 world rehearsal 替代训练时的一部分外部环境交互。策略在生成 tool call 后，不是总去调用外部环境，而是同时扮演环境，预测该 action 会触发什么 observation，再把 acting 和 rehearsal 联合优化。直观地说，它让模型在参数中内化“动作如何改变环境反馈”的关系。

**创新点**：它没有把 world model 做成独立模拟器，而是把环境动态作为 policy 的内部能力训练出来。对 Agent 后训练的启发是，工具调用轨迹中最有价值的不只是最终奖励，也包括 action-observation 的可预测结构。

**实验与 benchmark**：前 8 页列出 BFCL-v4、τ2-Bench、VitaBench、FinMCP-Bench 等 agentic benchmark。论文报告 EnvACE 在这些任务上整体优于 environment-scaling baselines，并且 test time 可以在不增加外部真实交互的情况下做 private rehearsal。

**可迁移价值**：适合用于低成本训练 tool-use reasoning：让模型先在内部预测工具响应，再把真实响应作为校准信号。对无法大规模开放真实环境的浏览器、金融、代码执行任务也有参考价值。

**局限**：前 8 页没有完整展示所有 benchmark 的详细表格；world rehearsal 是否会在复杂工具 API 上产生自洽但错误的虚拟反馈，需要进一步读后文。

### 3. TRAJDEBUG: Tracing Error Lifecycle to Identify Critical Failures in Long-Horizon Agent Trajectories

- 链接：https://arxiv.org/abs/2608.06346
- 方向：General Agent / Code Agent / Trajectory Debugging
- 评分：4.735
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：长程 agent 失败常常不是最后一步才错，而是早期一个小错误在后续观察和动作中级联放大。现有分析方法很难定位“最早且真正导致最终失败”的 critical error。

**核心方法**：TRAJDEBUG 把失败轨迹看成 error lifecycle，而不是孤立步骤分类。它结合多粒度历史压缩、基于证据的错误识别和错误状态追踪，判断一个错误是否被修复、是否继续影响后续步骤，以及它与最终失败的关系。

**创新点**：它把 agent debugging 从“找错误步骤”推进到“追踪错误生命周期”。对训练闭环 Agent 很有价值：轨迹监督不应只标 final outcome，还应标出早期误判、修复尝试、残留影响和 terminal impact。

**实验与 benchmark**：论文构造 TRAJERRBENCH，包含 486 条人工标注失败轨迹，来源覆盖 τ2-Bench 和 SWE-Bench Pro，因此同时包含真实工具使用和 coding 场景。前 8 页报告 TRAJDEBUG 在多种 agent benchmark 上整体优于已有 baseline，并能给下游 agent 改进提供可操作诊断。

**可迁移价值**：适合用作 Agent 训练数据审核器：失败轨迹不要整条丢弃，而是自动找关键错误、生成修复监督，并把“是否已从错误中恢复”作为中间 reward。

**局限**：具体模型对比数值和人工标注协议细节需要继续读后文；前 8 页主要确认 benchmark 规模、任务来源和方法框架。

### 4. AppDeltaWorld: Transition-Grounded Delta Code World Model for Mobile GUI Agents

- 链接：https://arxiv.org/abs/2608.05891
- 方向：General Agent / GUI Agent / World Model
- 评分：4.630
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：Mobile GUI agents 需要像人一样看屏幕并点击，但真实 app 轨迹涉及隐私、账号和敏感操作，难以大规模收集。现有 GUI world model 又常以图像或文本生成下一屏，容易出现布局不稳定、动作和状态转移不一致的问题。

**核心方法**：AppDeltaWorld 预测的不是一张自由生成图片，而是“可达的 code update”。系统在 action-transition 约束下检索 app-specific Level-1 HTML reference，再根据当前屏幕、动作、预测 next-screen text 和检索结构生成可执行 Level-2 HTML，最后把视觉资产插入 image slots 并通过浏览器渲染。

**创新点**：它把 GUI world model 从像素生成转成 transition-grounded HTML/code 生成。关键价值在于下一状态必须可渲染、可执行，并且受到 action transition 约束，更适合构造闭环训练环境。

**实验与 benchmark**：前 8 页确认 world modeling 使用 CMGUIBench-500 和 Code2World evaluation；action policy 使用 AndroidLens，并扩展到 MobileGym 和 MobileWorld。论文报告 AppDeltaWorld 在 CMGUIBench-500 上取得最高 fidelity，AppDeltaAgent 在 AndroidLens 达到 SOTA，并在 MobileGym 从 10.2% 提升到 14.1% SR、MobileWorld GUI-only SR 从 9.4% 提升到 14.9%。

**可迁移价值**：适合 GUI/Browser Agent 训练环境构造：用 DOM/HTML delta 表示状态转移，再用渲染器形成可观察屏幕，减少纯图像 world model 的漂移。

**局限**：目前证据主要来自移动 GUI；迁移到桌面软件、复杂浏览器应用或动态网络请求场景，还需要更多验证。

### 5. AgentOPSD: Recursive Self-Distillation for Agentic Reinforcement Learning

- 链接：https://arxiv.org/abs/2608.05987
- 方向：General Agent / Agentic RL / Credit Assignment
- 评分：4.610
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：RLVR 给长程 agent 任务提供 trajectory-level advantage，但关键决策往往只发生在少数 turns。若奖励只在整条轨迹层面分配，模型很难知道到底是哪一步工具调用或搜索动作带来成败。

**核心方法**：AgentOPSD 做 recursive self-distillation，把历史相关的 belief 更新作为自蒸馏信号，并通过相邻状态之间的 marginal revision 找到 pivotal turns。它兼容标准 policy optimization，不需要额外 rollouts。

**创新点**：它把自蒸馏从“整段答案更像优解”细化到 agent 轨迹中的 turn-level credit assignment。对工具使用训练来说，这相当于给关键动作更密集的学习信号。

**实验与 benchmark**：前 8 页显示实验覆盖 ALFWorld、WebShop 和 Search-QA，并使用 Qwen 3B/7B 两个尺度。论文报告 AgentOPSD 优于 GRPO 和强 self-distillation baselines，在 Qwen2.5-7B 的 ALFWorld 上达到 89.1% success；消融把收益归因于 turn-level aggregation 和 history-dependent recursive belief updates。

**可迁移价值**：适合和搜索、代码执行、GUI 操作任务结合：把长轨迹拆成多个 belief revision 点，训练模型识别哪些观察真正改变后续动作。

**局限**：前 8 页能确认 benchmark 和主要结论，但完整任务级结果表较密集，部分细粒度数字需要读后文核验。

### 6. When History Lies: Evaluating and Improving Tool Use under Misleading Multi-Turn Histories

- 链接：https://arxiv.org/abs/2608.06057
- 方向：General Agent / Tool Use / Multi-Turn Robustness
- 评分：4.510
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：工具调用 Agent 依赖历史消息和工具轨迹判断当前状态。但多轮任务中，旧历史可能仍然格式正确、语义也看似合理，却已经不再适用于当前请求。模型容易复用过期实体、旧接口约定或污染状态。

**核心方法**：论文提出 ContextPollute-Bench，用 paired Original、Polluted、Oracle State 视图同步控制系统策略、当前工具、最新请求和 gold next action。它设计 11 种 gold-preserving interventions，分别测试 decision state、entity binding 和 interface execution 的污染。

**创新点**：这篇把工具历史污染做成可控 benchmark，而不只是泛泛讨论“上下文太长”。它还提出 Oracle-OPD，让 Oracle-conditioned teacher policy 通过 soft supervision 迁移给只能看到污染历史的 student。

**实验与 benchmark**：前 8 页报告，在 Qwen3-1.7B 上，污染会翻转 32.1% 原本正确的决策。Oracle-OPD 在 Qwen3-1.7B 上达到 87.0% Balanced Tool-Use Accuracy，高于 Gold-SFT 的 66.3%、Oracle sequence distillation 的 82.3% 和 off-policy token distillation 的 85.0%；8B teacher 可把同一 1.7B student 提升到 91.9%，8B student 达到 93.0%。

**可迁移价值**：适合加入 Agent runtime 的状态判别层：最新请求、可用工具、实体绑定和历史结论需要显式重验证。训练数据也应包含“看似合理但已过期”的污染历史。

**局限**：目前是构造型 benchmark；真实产品中的历史污染会混合权限、用户偏好、工具版本和外部状态变化，复杂度更高。

### 7. HarnessOpt-Bench: Evaluating LLMs at Harness Optimization

- 链接：https://arxiv.org/abs/2608.06301
- 方向：General Agent / Harness Optimization / Evaluation
- 评分：4.390
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：Agent 能力不只来自模型权重，还来自 harness：prompt、工具、控制流、记忆和 orchestration code。自动优化 harness 是提升 AI 系统的重要路径，但目前缺少统一 benchmark 衡量模型是否真的会迭代改进 harness。

**核心方法**：HarnessOpt-Bench 把一个 optimizer LLM 与 coding harness 配对，给它 seed harness、graded evaluation feedback 和固定目标评估预算。optimizer 需要编辑 harness 并提交最终候选，最终按 held-out test partition 上相对 seed 的 normalized gain 评分。可信执行环境负责边界隔离、资源计量和版本审计。

**创新点**：它把“改 prompt/工具流/记忆策略”变成可评测的端到端工程任务，而不是人工调参经验。对 Agent 研究来说，这提供了评估自动系统改进能力的协议。

**实验与 benchmark**：前 8 页显示评估 5 个 frontier LLM optimizer，包含 shared coding harness 和 native harness 设置，覆盖 4 个下游任务、111 个 scored runs。论文报告 optimizer model 之间的差异比其使用的 coding harness 差异更显著。

**可迁移价值**：可用于训练“自改进 Agent”：输入评估反馈和资源预算，让模型修改 prompt、工具选择、memory policy 或控制流，再用 held-out 评估防止过拟合。

**局限**：前 8 页未完整列出 4 个任务的所有细节和结果表；需要继续确认 benchmark 是否足够覆盖真实复杂 agent harness。

## Search Agent

### 8. Contextual Information Policy Optimization for Search Agents

- 链接：https://arxiv.org/abs/2608.06128
- 方向：Search Agent / Evidence Use / Reinforcement Learning
- 评分：4.570
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：Search Agent 的可靠性不只取决于能否检索到相关证据，还取决于检索后的推理是否真的被证据改变。现有 RL 往往奖励最终答案正确或中间进展，却不直接评估 post-retrieval actions 是否 grounded in retrieved evidence，导致模型先用内部知识下结论，再用搜索结果做确认。

**核心方法**：CIPO 显式奖励 evidence-oriented reasoning。它给被检索信息影响的 reasoning actions 分配 dense turn-level credit，并把 evidence-use signal 与全局结果奖励结合。论文强调 CIPO 不需要人工过程标注，也不需要额外 reward model。

**创新点**：它把 Search Agent 的训练目标从“答对”改成“答题过程中正确使用外部信息”。这对 fact seeking、deep research 和 citation-grounded RAG 很关键，因为模型需要学会让新证据改变后续搜索和推理。

**实验与 benchmark**：前 8 页报告，CIPO 在 7 个 in-domain 和 out-of-domain benchmarks 上实验，能减少 prior-driven reasoning，并在多数任务上取得强表现。

**可迁移价值**：适合作为搜索轨迹训练信号：每次检索后判断后续 action 是否引用、整合或修正了证据，而不是只看最终答案。

**局限**：前 8 页没有完整列出 7 个 benchmark 的全部名称和逐项结果；需要读后文确认在长报告生成任务上的表现。

### 9. HERALD: Counterfactual Audits and Minimal Repairs for Proof-of-Retrieval Rewards

- 链接：https://arxiv.org/abs/2608.06012
- 方向：Search Agent / Retrieval Reward / Citation Grounding
- 评分：4.445
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：Search-agent reward 常混合答案质量、引用 grounding、工具成本和反作弊项。高 reward 不一定代表引用证据真的被检索到，某些 penalty 还可能相互抵消，导致 citation laundering。

**核心方法**：HERALD 是一个 offline audit。它做 same-question counterfactual interventions，区分 candidate-visible 和 oracle information，并在 policy optimization 前枚举 detector contracts。发现奖励漏洞后，再寻找最小修复项，而不是盲目加更多惩罚。

**创新点**：它把 proof-of-retrieval reward 当作可审计对象，强调“奖励函数是否真的证明模型检索过证据”。这对 Search Agent 的 RL 很重要，因为 citation reward 一旦被套利，会直接训练出会编引用或洗引用的策略。

**实验与 benchmark**：前 8 页报告在 HotpotQA、2WikiMultiHopQA 和 MuSiQue 的 Qwen3-8B pools 上测试。原始奖励可拒绝 search deletion 和 fake IDs，但 label-free citation-laundering attack 会成功；针对“引用未检索 corpus passage”的最小修复使经验 ASR 为 0，并给出 0.50% one-sided cluster upper bound。在 5M-token matched training、每 benchmark 256 paired questions 下，修复版在 HotpotQA 和 2Wiki 满足 EM non-inferiority gate，但 MuSiQue 未满足；citation precision 和 support recall 分别提升 2.02 和 1.46 点，unsupported citations 下降 1.69。

**可迁移价值**：适合加入 Deep Research Agent 的奖励审计：训练前先用反事实删除、替换、伪造引用 ID 测 reward 是否可被攻击，再用最小修复降低过拟合风险。

**局限**：HERALD 主要审计 proof-of-retrieval reward；它不能替代事实正确性、综合质量和长报告结构的完整评估。

## Code Agent

### 10. When Self-Evolution Backfires: Pre-Commit Gating against Skill Contamination in LLM Agents

- 链接：https://arxiv.org/abs/2608.05810
- 方向：Code Agent / General Agent / Skill Memory
- 评分：4.305
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：自演化 Agent 会从执行轨迹中蒸馏 reusable skills，并把它们加入长期 skill pool。但论文发现能力并不一定随 skill pool 增大而单调提升：坏 skill 进入上下文后，会影响后续 skill 蒸馏，形成跨轮污染链。

**核心方法**：论文提出 Verifier-as-Gatekeeper (VaG)。每个新 skill 在进入 runtime context 前，先经过三类异构 critics：structural validity、behavioral harmlessness 和 semantic consistency；高层再做 marginal-gain subset selection，避免组合污染。

**创新点**：核心观点是 skill admission 必须 pre-commit，而不是等性能下降后再 rollback。因为后续 skills 已经吸收了坏 skill 的推理模式，事后删除源 skill 只能恢复很小一部分损失。

**实验与 benchmark**：前 8 页报告，在 Terminal-Bench 2 上，无条件 skill accumulation 先升后降；VaG 则每轮提升，达到 72% pass@1，且 skill pool 约小 5 倍。冻结后的 skill pool 可正迁移到四个其他 backbone 和第二个 benchmark；消融显示三类 critics 互补且不可互相替代。

**可迁移价值**：对 Code Agent 特别重要：把失败经验写成 skill 前必须验证其结构、行为和语义一致性。适合用于长期 coding assistant 的 memory/skill 管理，避免错误修复模式被反复检索。

**局限**：前 8 页确认了 Terminal-Bench 2 结果和 VaG 机制，但具体第二 benchmark、backbone 列表和错误 skill 类型分布需要读后文。

## 值得关注但未进 Top 10

- Comparative Approaches to Agent Retrieval over Large Skill Libraries：https://arxiv.org/abs/2608.06196。它评估 690 个 skills 和 117 个真实查询，hybrid ranker top-5 命中 73.5%±8.0，typed graph 在等 token 预算替换 additional ranked results 时反而低 11.2 点。对 skill retrieval 很有参考价值，但相比 VaG，它更像系统检索评测，训练数据启发略弱。
- Personalized Deep Research Query Refinement with Graph-Scaffolded Evidence Grounding：https://arxiv.org/abs/2608.05876。G-STEER 用 Intent Elicitation Graph 训练 query refinement policy，在 PDR-Bench 上提升 personalization，并把用户追问降到强 clarification baseline 的约三分之一。它与 Search Agent 很相关，但更偏需求澄清和个性化 query 前处理。
- Beyond Top-K: Replacing Black-Box Retrieval with Interpretable Agentic Operations：https://arxiv.org/abs/2608.06305。摘要显示它批评长文档 RAG 的 chunk top-k 设计，并主张可解释 agentic operations，适合作为 Search Agent 检索结构改造线索；本次未下载 PDF，证据仅到摘要级。

## 今日重点趋势

1. Agent 训练数据正在从“可执行即可”转向 solver-relative learnability。CalibForge 和 EnvACE 都强调，训练任务和环境反馈需要与 solver 能力、动作后果、可验证轨迹绑定。
2. 长程轨迹的中间状态越来越重要。TRAJDEBUG、AgentOPSD、CIPO 都在不同层面把监督从 final answer 拆到错误生命周期、turn-level credit 或 evidence-use action。
3. Agent memory/skill/harness 正在成为核心研究对象。VaG 关注 skill 污染，HarnessOpt-Bench 关注 prompt、工具、控制流、记忆的整体优化，说明“模型外系统”已经是 agent 能力的重要组成。
4. Search Agent 的奖励正在走向可审计。HERALD 和 CIPO 都在防止模型只做表面检索或引用套利，而是要求证据真正进入推理链。

## 潜在研究 idea

- 用 CalibForge 式 multi-solver calibration 构造 Code Agent 任务：同一 issue 让小 scout、强 fixer、验证器分别尝试，保留强弱差异明显且可复现的任务。
- 把 TRAJDEBUG 的 error lifecycle 标注加入 RL 训练：失败轨迹不只给 0 reward，而是给“首个关键错误”“已恢复错误”“未恢复错误”三个层次的监督。
- 在 Deep Research Agent 中组合 CIPO 和 HERALD：先训练模型让检索证据真实影响后续推理，再用反事实 reward audit 检查 citation laundering。
- 对长期 coding assistant 引入 VaG 式 skill gate：每条经验进入 memory 前必须绑定可复现命令、适用条件、反例和行为无害性检查。

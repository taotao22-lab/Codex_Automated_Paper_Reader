## General Agent

### 1. Hear, Invoke, and Understand: A Skill-Calling Multimodal Agent for Large Audio Language Models

- 链接：https://arxiv.org/abs/2608.01881
- 方向：General Agent / Tool-use Reasoning / Multimodal Agent
- 评分：4.885
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：现有大音频语言模型多半把音频当作固定输入来回答问题，遇到需要分离、重听、识别、检索、转换或多步声学操作的任务时，模型缺少“决定何时调用哪个技能、如何解释工具返回结果、再决定下一步”的机制。论文把这类任务定义为 tool-interactive audio reasoning，即模型不能只靠内部表征直接回答，而要围绕外部 skill/tool 形成交互轨迹。

**核心方法**：作者提出 SpeechAgent-R。系统有一个技能库，每个 skill 由自然语言说明和若干工具接口组成；agent 在每一步根据当前问题、音频、已检索的 skill 文档、历史动作和工具观察，决定检索 skill、调用工具或结束回答。训练上先构造 HIU-Corpus，再用轨迹级 SFT 学会结构化交互行为，之后用 multi-turn RL 优化多步决策。数据构造不是简单问答，而是把音频任务转成 direct-answer 与 skill-assisted 两类轨迹，记录工具调用和返回观察，并用模型与人工校验修正错误轨迹。

**创新点**：它的价值不在“音频”本身，而在把 tool use 从 prompt 中的工具名选择推进到“技能文档检索、工具接口选择、中间观察整合、多轮行动优化”的完整训练协议。HIU-Corpus 包含 65,492 条交互轨迹、507.6 小时音频、24 个任务、8 类技能和 9 个工具；HIU-Bench 又扩展到 1,395 个样本、56 个任务和 26 个工具，并设置 ID/OOD split，OOD 与 ID 只有少量工具重叠且 workflow 变化明显。

**实验与 benchmark**：HIU-Bench 评估任务完成、交互质量和泛化。论文报告 SpeechAgent-R 总分 80.05，相比同一 agent harness 下的 base model 提升 15.04；ID 任务 84.17，OOD 任务 70.94，分别提升 15.40 和 14.23 点。它还明确对比了只做音频推理或固定流程工具调用的 audio agent。

**可迁移价值**：可以直接借鉴到 General Agent 后训练：把“技能说明 + 工具接口 + 调用轨迹 + 工具观察 + 最终答案”作为训练样本最小单元，并用 OOD workflow 测试 agent 是否真的学会组合工具，而不是记住固定模板。对代码 agent 也有启发：skill 文档可以对应测试、搜索、编译、调试、patch 等工具说明。

**局限**：领域集中在音频，多数工具与声学处理相关；工具真实执行成本、错误工具输出的鲁棒性和跨领域技能迁移仍需额外验证。

### 2. DGA2D: Directed Graph-Guided Automated Algorithm Design with Large Language Models

- 链接：https://arxiv.org/abs/2608.00700
- 方向：General Agent / Code Agent / Closed-loop Program Search
- 评分：4.570
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：LLM 做自动启发式算法设计时，常见做法是在固定 solver 模板里改局部模块，搜索空间被人为限制；一旦让模型同时改算法框架和算子代码，又会遇到生成算子不可靠、搜索空间巨大、不同模块贡献难以归因的问题。

**核心方法**：DGA2D 把完整算法表示成有向图：节点是功能算子，每个节点有多个候选代码实现；一条 directed walk 对应一条完整算法 pipeline。LLM 有三类动作：改节点内的代码实现、调整算子之间的连接拓扑、为当前路径选择最合适的实现。系统对生成算法在 benchmark 实例上执行评估，并用 first-order path-dependent credit assignment 给“某个算子实现在某个前驱上下文中是否有用”分配信用，避免只看单个模块的全局平均表现。

**创新点**：这篇论文把“代码生成”提升成“可执行算法结构搜索”。它不像简单 self-refine 只对代码片段打分，而是显式维护一个可组合的 operator graph，并将执行反馈回流到结构和实现两个层级。这种表示适合迁移到 Code Agent 的补丁搜索、测试策略搜索和工具链编排：一次 patch 可以看成若干操作节点的路径，信用分配可以从“最终 CI 成败”反推到具体操作组合。

**实验与 benchmark**：论文在 12 个 NP-hard 组合优化领域评估，包括调度、路径规划、装箱和图问题；正文重点展示 FJSP、TSP、3D-CLP、MIS。基线包括 OR-Tools CP-SAT、ILS、POMO/ReSched/SDDS/BPP-DRL 等学习型方法，以及 EoH、MCTS-AHD、MEoH、ReEvo 等 LLM-based AHD 框架。每个问题 evolution/test split 分离，生成算法在相同运行协议下执行，编译失败、运行错误、不可行解或超时都给最低 fitness。论文报告在 DeepSeek-V4-Flash 下平均 normalized gap 从最强基线的 15.69% 降到 6.02%，在 GPT-5.6 Sol 下最多降低 10.96 个百分点。

**可迁移价值**：适合用于 agentic post-training 的“执行反馈数据构造”：让模型生成可执行 pipeline，而不是单步答案；将失败类型作为 reward shaping；把结构搜索与代码实现搜索分开记账。

**局限**：评估成本高，每个候选都要执行；生成算法的可读性、初始 operator pool 质量和跨模块不一致仍是风险。论文也承认未来需要更强的 program-invariant checking。

### 3. A Self-Triggered Agentic Push Recommendation System

- 链接：https://arxiv.org/abs/2608.01949
- 方向：General Agent / Industrial Closed-loop Agent
- 评分：4.035
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：推送推荐不是只排序候选内容，还要决定“是否推、何时推、下一次什么时候再检查”。预先规划频次缺少实时性，固定间隔轮询又浪费算力并可能打扰用户。论文将工业推送系统重新表述为 self-triggered agentic process。

**核心方法**：STEPS 由 planning agent、execution agent 和 filtering agent 组成。planning agent 用 Decision Transformer 和 gated ordinal regression 预测下一次系统唤醒时间；execution agent 在计划时间到达时判断是否发送，并用 Bellman/RTG 形式修正离线日志里的次优行为；filtering agent 在早期过滤低价值或异常计划，避免重型执行排序消耗算力。系统闭环控制的不只是 action，还包括下一次被调用的时间。

**创新点**：这篇不是 LLM 论文，但 agent 系统抽象很强：它把调度、执行、护栏分为三个 agent，并把下游过滤结果通过 end-to-end RTG 反馈到 planning。对通用 agent 来说，这提示我们训练长程任务时不应只优化最终成功，还要优化“何时重新观察环境、何时停止、何时进入昂贵工具”。

**实验与 benchmark**：论文在抖音线上 A/B 中对比 pre-planned frequency 与 fixed-interval triggering。指标包括 User Active Days、Negative Experience（撤销推送权限）和 Resource Consumption。STEPS 相对基线提升 UAD 0.2843%，降低权限关闭率 1.9089%，filtering agent 将计算开销降低 79.42%。消融显示 planning、execution、filtering 均有贡献，其中 filtering 单独带来约 74.88% 的资源下降。

**可迁移价值**：适合借鉴到 Browser/Computer Agent 的 runtime 策略：planning 负责下一次检查或工具调用时间，execution 负责真正行动，filtering 负责在昂贵工具前做轻量 gating。

**局限**：任务是推荐推送，用户行为 reward 与通用任务成功率不同；线上实验细节依赖工业平台，复现难度高。

## Search Agent

### 4. Advancing Relevance Measurement with Vision-Language Models for Web-Scale Search

- 链接：https://arxiv.org/abs/2608.02446
- 方向：Search Agent / Relevance Judge / Evaluation Pipeline
- 评分：4.345
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：搜索系统上线 A/B 时，点击、保存等 engagement 指标不能保证结果真的满足查询意图；人工 relevance annotation 成本高、周期长，难以覆盖足够多 query 和实验。对于 Search Agent，类似问题是：如何让模型输出的检索路径、证据选择和答案相关性被可扩展地评估。

**核心方法**：Pinterest Search 部署了 VLM-based automated relevance evaluation pipeline。作者用约 80 万人工标注 query-Pin pair 微调 Qwen3-VL，将 query、Pin 图像和多种文本元数据输入模型，输出 1-5 级 relevance label。然后用 VLM label 支撑线上 A/B 的 query-level sDCG@K，并结合分层 query sampling 降低方差。

**创新点**：它不是提出新模型结构，而是给出生产级“自动相关性评测”闭环：先验证 VLM 与人工标签在 query-level metric 上对齐，再将更便宜的标签能力转化为更大的 query set、更好的 sampling design 和更低 MDE。对 Search Agent 的训练评估很有启发：自动 judge 不应只看单条标签准确率，还要看它是否能在实验对比中保持低偏差的 paired difference。

**实验与 benchmark**：论文报告 query-level sDCG@K 的 VLM-human 平均误差在不同 query popularity segment 下低于 0.03，P10/P90 在 [-0.1, 0.1] 内；Qwen3-VL-4B 与 8B 表现接近，4B 因成本更低用于生产。采用 VLM labeling 后，relevance measurement jobs 增加 4 倍以上，标注 turnaround time 提升 20 倍以上，单标签成本降低 99% 以上，MDE 下降约 6 倍。还验证了法语、德语、巴西市场的迁移，非英语有偏差但 paired difference 接近 0。

**可迁移价值**：可用于构建 Search Agent 的自动评测器：用人工小样本校准 judge，用 query 分层降低评估方差，用 paired difference 评估新 agent 是否真实改进，而不是只看离线准确率。

**局限**：场景是图文 Pin 搜索，不等同于开放网页检索；训练数据与生产流量私有，外部难以复现。

### 5. Requirement--Evidence Alignment for Compositional E-Commerce Queries

- 链接：https://arxiv.org/abs/2608.02500
- 方向：Search Agent / Reranking / Constraint-grounded Retrieval
- 评分：4.085
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：复杂查询通常包含多个约束，例如预算、兼容性、属性和排除条件。传统 reranker 常把这些条件压成一个总体相关性分数，结果会把“主题相近但违反约束”的候选排在前面。

**核心方法**：REAlign 将查询拆成 typed requirements，并为候选构造可见 evidence card，显式判断每个条件是 satisfied、violated 还是 unsupported。训练时构造 requirement-targeted contrasts，让模型看到“为什么这个近似候选应该输”；优化时使用 Requirement-Aware Group-Relative Policy Optimization，在 partial ranking 中同时优化相关性、条件满足、证据支撑和去重。

**创新点**：这篇对 Search Agent 的价值在于把检索结果从“相似文本”转成“可验证条件集合”。如果 agent 要检索证据回答问题，可以把用户问题拆成要求，把网页片段标注为支持/违反/缺失，再把 reranking reward 与这些诊断项绑定。

**实验与 benchmark**：论文使用两个 fixed-pool e-commerce reranking benchmark：Shop-Need 和 KS-Need，均包含组合要求。所有方法使用相同 Qwen3.5-4B backbone、相同 SFT 初始化和匹配训练预算。指标包括 NDCG、HR、ReqSat、Violation、Evidence、Reward 和可解析 ranking 比例。结果显示 R-GRPO 在两套 benchmark 上整体排序最好，并降低 top ranks 的 violation；消融表明 query requirement graph 与 candidate evidence card 互补。

**可迁移价值**：适合做检索增强 agent 的 reward 设计：不仅奖励 final answer，还奖励“每个子要求是否被证据满足”，并把 unsupported 与 violated 区分开。

**局限**：数据来自电商固定候选池，开放网页的证据噪声和候选动态生成没有充分覆盖。

### 6. Real-Time Hybrid Retrieval in Hyperbolic Space for Retrieval-Augmented Generation on Edge Devices

- 链接：https://arxiv.org/abs/2608.01450
- 方向：Search Agent / Edge RAG / Hybrid Retrieval
- 评分：3.815
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：边缘设备上的 RAG 需要低延迟和低资源占用，但传统 dense retriever 多在欧氏空间工作，对层级化语义结构表达不足；纯 BM25 又难以处理语义匹配。

**核心方法**：论文提出一个 Lorentz hyperbolic geometry 下的混合检索系统。系统先用 BM25 做词法召回，再将预训练 word embedding 通过 HyTE-H 投影到双曲空间，使用 Lorentzian inner-product similarity 重排候选。双曲空间的指数体积增长适合表达自然语言里的层级结构。

**创新点**：对 Search Agent 来说，它提供了一个低资源检索模块设计：先用便宜词法召回控制候选规模，再用结构化几何空间增强重排。相比大型 cross-encoder judge，它更适合作为本地 agent 的第一阶段 memory/search primitive。

**实验与 benchmark**：摘要和前 8 页说明系统关注 RAG edge deployment、两阶段检索、可调 BM25/semantic fusion。具体 benchmark 与完整数值在抽取的前 8 页中信息有限，因此日报不扩展未核实结果。

**可迁移价值**：适合作为长上下文 agent 的本地记忆检索模块候选，尤其是层级文档、API 文档和代码库符号索引。

**局限**：论文更偏检索系统工程，缺少 agent 级任务闭环评估；本文仅能核验前 8 页信息。

### 7. UniHEAR: Unified Heterogeneous-Source Attentive Retrieval for Knowledge-Based Visual Question Answering

- 链接：https://arxiv.org/abs/2608.01147
- 方向：Search Agent / Multisource Retrieval / RAG
- 评分：3.780
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：KB-VQA 需要从外部知识源检索实体和章节。单一模态召回会漏掉只在另一种源中可见的实体；普通 dual-tower reranker 又忽略候选来自哪个检索源，导致冗余依赖或错误过滤。

**核心方法**：UniHEAR 用 Coarse Retrieval Descriptor 记录多源召回证据，再在 reranking 阶段使用 Retrieval-Guided Attentive Modality Gating，根据候选的召回来源和先验调整图文模态权重。最后 Multi-Entity Section-Augmented Generation 按 rank 分配多个实体的相关章节，供 MLLM 生成答案。训练时用 contrastive loss 学融合表征，并用辅助 loss 保持跨模态匹配能力。

**创新点**：它把“检索来源”变成 reranker 可见特征，而不是把所有候选混在一起排序。Search Agent 可借鉴这一点，把网页搜索、文档库、代码搜索、记忆库的来源可靠性作为 reranking 条件。

**实验与 benchmark**：评估使用 E-VQA 和 InfoSeek。E-VQA 包含 1M triplets、约 16.7K 实体，评估 4.7K 单跳样本和 2M Wikipedia articles；InfoSeek 包含 1.3M triplets，验证/测试覆盖 unseen entities 和 novel questions。指标包括 Recall@k、BEM、VQA accuracy 和 relaxed accuracy。论文报告相对最强专用 reranker OMGM，Recall@1 在 E-VQA 和 InfoSeek 上分别提升 6.7 和 1.2 点；在 VQA 任务上使用高质量检索上下文也带来提升。

**可迁移价值**：适合多源 RAG agent：将“来源、rank、相似度、可用模态、历史可靠性”压成粗粒度 descriptor，再用于精排和上下文预算分配。

**局限**：主要面向视觉问答和 Wikipedia 实体知识，开放网页事实核验、长链搜索轨迹没有直接评估。

## Code Agent

### 8. Tevatron Meets Megatron: Expert-Parallel LLM Reranker Training on an Academic Budget

- 链接：https://arxiv.org/abs/2608.00916
- 方向：Search Agent / Code Infrastructure / Reranker Training
- 评分：4.175
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：强 reranker 训练开始使用 billion-scale cross-encoder、MoE backbone 和 distillation，但学术组常用的 Hugging Face Trainer + DeepSpeed/FSDP 对 MoE、并行重计算和吞吐支持不足。对 Search Agent 来说，reranker 是核心组件；训练基础设施限制会直接限制可复现研究。

**核心方法**：Tevatron 3.0 将 Megatron-Core backend 接入 Tevatron reranker toolkit，同时保留数据路径、评估流程和 Hugging Face 可加载 checkpoint 格式。它支持 tensor/pipeline/expert parallelism，使用 HF/Megatron 权重转换，并保持 reranker 的 scoring 接口：在最终 prompt 位置取 yes/no token logit 差作为 relevance score。

**创新点**：这篇的工程价值强：它不是重做一个检索框架，而是在不迁移数据和评估接口的情况下替换训练后端。对 agent 研究来说，这意味着可以用同一 BEIR/MTEB/私有 benchmark registry 训练 dense、MoE 或 distillation reranker，并把实验差异压到训练后端本身。

**实验与 benchmark**：论文评估 BEIR-15 的 NDCG@10，提供 local score-only 和 remote rerank-and-score 两种评估 schema；还展示 8B dense 与 30B-A3B MoE reranker 训练。结果说明 Megatron 与 FSDP 路径在 reranker quality 上几乎一致，full-parameter path 每个 first stage 差异在 0.002 NDCG@10 内；MoE reranker 在较少 activated parameters 下接近 dense-8B 质量并有更高推理吞吐。

**可迁移价值**：如果要训练 Search Agent 的检索评估器或 reranker，这篇提供了可复用工程路径：固定数据和评估注册表，只替换并行训练后端。

**局限**：论文重点是 reranker 基础设施，不直接评估完整 agent；实际复现需要 H200/大 GPU 环境。

### 9. Lossless Tensor Compression as Program Synthesis

- 链接：https://arxiv.org/abs/2608.02162
- 方向：Code Agent / Program Synthesis / ML Systems
- 评分：3.945
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：模型 checkpoint 越来越大，通用压缩器不了解 tensor 结构，专用压缩器又常依赖固定格式。论文将无损 tensor 压缩转成程序合成问题。

**核心方法**：Brevis 定义一个 typed DSL，包含可逆算子，用来描述 tensor 中重复区域、浮点字段等结构。给定 tensor 后，系统合成一个自包含 DSL program，能 bit-exact 重建原 tensor。这样压缩文件不只是字节流，而是“可执行重构程序”。

**创新点**：对 Code Agent 的启发在于：把数据变换、压缩、修复等任务表达成受类型约束的 DSL，再由搜索/合成器产生可验证程序。它比自由生成代码更容易验证，因为重建结果必须 bit-exact。

**实验与 benchmark**：前 8 页显示论文包含 checkpoint-specific pipeline、实现和公开 artifact，并在多个 tensor/checkpoint 场景上评估压缩率与可复原性。抽取文本显示 GitHub artifact 可用，但完整表格数值主要在后文，本文不编造未核验数值。

**可迁移价值**：可用于 Code Agent 的 constrained synthesis 训练样本：输入结构化对象，输出 DSL 程序，再以可执行一致性作为 reward。

**局限**：目标是 tensor 压缩，不是通用代码修复；迁移到软件工程任务需要重新设计 DSL 和验证器。

### 10. P4-SpecTec: Integrating a Language Mechanization Framework into the Real-World P4 Specification

- 链接：https://arxiv.org/abs/2608.00639
- 方向：Code Agent / Formalization / Executable Specification
- 评分：3.870
- 证据来源：arXiv PDF 前 8 页 + 摘要

**问题背景**：编程语言规范、实现、测试和形式化经常随演化而分叉。P4 有官方规范和 p4c 编译器，但规范不是 normative，语义存在非正式、遗漏和歧义，导致实现与文档难以同步。

**核心方法**：P4-SpecTec 将 P4 语法、类型系统和动态语义机械化为可执行的元语言规则，并能生成类型检查器、解释器和规范 prose。核心技术是 algorithmic inference rules：既保持规范可读，又让类型系统和语义可执行。项目还与 P4 官方规范 authoring toolchain 集成，未来规范更新可在 meta-language 层完成，并用 p4c test suite 验证。

**创新点**：这篇对 Code Agent 很重要，因为它展示了“文档即可执行规范”的工程形态。若要让 Code Agent 修复编译器、语言服务或 API SDK，最可靠的环境不是自然语言文档，而是可执行规范 + 测试套件 + 反例。

**实验与 benchmark**：论文称机械化覆盖 P4 1.2.5 的语法、类型系统和动态语义，排除并发、未定义值、实现相关特性和未解决语义；在过程中发现并报告 24 个 bug。前 8 页还说明将用 p4c test suite 比较 formalization 和 P4-SpecTec。

**可迁移价值**：可作为 Code Agent 评测环境模板：将规范、解释器、类型检查器和测试统一到一个可执行源，agent patch 后必须同时满足 prose 生成、解释执行和 test suite。

**局限**：领域是 P4 DSL，且不覆盖并发等复杂语义；对主流通用语言迁移需要大量规范工程。

## 今日重点趋势

1. **Agent 训练正在从“答案监督”转向“轨迹监督 + 工具观察 + 多轮 RL”**。SpeechAgent-R 是今日最直接例子，DGA2D 和 STEPS 也都强调执行反馈与信用分配。
2. **Search Agent 的评估开始工程化**。Pinterest VLM relevance judge 说明，自动评估器要先通过人工对齐和实验级 paired difference 校验，再用于生产规模采样。
3. **闭环系统越来越重视成本控制**。STEPS 的 filtering agent、Tevatron 的训练后端替换、edge RAG 的双阶段检索都在处理“何时调用昂贵模块”。
4. **Code Agent 可借鉴形式化与 DSL 思路**。P4-SpecTec 和 Brevis 都把自由文本/自由代码压进可执行、可验证的中间表示，适合降低 agent 生成错误。

## 潜在研究 idea

1. **Skill document + tool trajectory 数据格式**：参考 HIU-Corpus，为代码工具链构造 `skill_doc -> tool_call -> observation -> next_action` 轨迹，覆盖搜索、测试、编译、patch、review。
2. **Agent 工具调用的 first-order credit assignment**：借鉴 DGA2D，对连续两个工具/操作的转移打分，而不是只奖励最终成功，减少长链任务 reward 稀疏。
3. **Search Agent 的 VLM/LLM relevance judge 校准协议**：用小规模人工标签校准 judge，并报告 query-level paired difference、MDE 和分层采样收益，而不是只报告 accuracy。
4. **昂贵工具前的 filtering policy**：把 STEPS 的 filtering agent 迁移到浏览器/代码 agent，在调用大模型评审、完整测试套件或网页批量抓取前先做轻量 gating。
5. **Requirement-evidence reward**：把用户目标拆为 typed requirements，要求检索片段标注 satisfied/violated/unsupported，用于训练 RAG reranker 和最终答案 verifier。

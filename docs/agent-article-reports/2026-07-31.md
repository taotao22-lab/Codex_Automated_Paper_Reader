## Top 10

### 1. Qwen-UI-Agent Technical Report: Toward Next-Generation Real-World Centric Foundation GUI Agents

- 方向：General Agent / GUI Agent / Computer-use
- 核心方法：这篇报告把 GUI Agent 设计成跨 mobile、desktop、web、DeepSearch 的基础执行器，而不是单一网页点击模型。它的关键点是统一 action space：模型可以在 GUI 操作和 CLI 执行之间切换，并且一次生成批量动作，用来减少多步工作流中的等待和上下文损耗。系统还引入大规模真实设备 mobile runtime、沙箱环境和 AutoResearch 式数据飞轮，让 Agent 自动构造任务、诊断失败并规划下一轮训练数据。
- 创新点：相对一般 GUI benchmark 论文，它更像一套可扩展 post-training 基础设施。对你的研究最有价值的是“真实设备/沙箱混合 runtime + 长轨迹在线 RL + 自动任务迭代”的组合，这直接对应真实工具使用能力迁移。
- 实验与 benchmark：摘要和前 8 页报告了 MobileWorld 82.1%、MobileWorld-Real 92.2%、AndroidDaily 97.5%、OSWorld-Verified 79.5%、OSWorld-v2 partial-progress 40.0%、WebArena 73.6%、ScreenSpot-Pro 81.5%。这些 benchmark 分别覆盖移动端操作、桌面状态改变、浏览器任务和 GUI grounding。
- 可迁移价值：适合作为 Agent 训练系统设计参考，尤其是统一动作接口、跨平台 runtime、批量动作生成和 100+ turn 轨迹训练。
- 局限：前 8 页主要是技术报告式概览和结果摘要，具体数据清洗、环境失败修复和 RL reward 细节需要继续读正文后半部分。
- 证据来源：arXiv PDF 前 8 页。

### 2. Echoverse: Deep, Evolving Environments for Training Computer-Use Agents at Scale

- 方向：General Agent / Computer-use training environment
- 核心方法：Echoverse 关注一个很实际的问题：Computer-use Agent 只有在可交互、可破坏、可重置的应用里才能学到动作后果。论文把环境规格编译成带状态的应用，任务由应用数据库中的真实状态变化来判分。它还设计了 co-evolution loop：同一条 graded rollout 既用于修复环境、任务和 verifier，也作为模型训练信号。
- 创新点：它没有停留在“生成很多网页环境”，而是强调环境深度、失败定向和环境随模型共同进化。这个思路适合迁移到 Search/Code Agent：训练环境不应只是静态题库，而应能暴露长程失败、验证中间状态，并根据失败自动补充任务。
- 实验与 benchmark：论文报告在 12 个环境上训练 9B 模型，14 个评测 split 平均从 36.5% 提升到 67.1%；深环境相对浅环境能把 live-site accuracy 从 80.0 提到 85.0、从 48.0 提到 65.0；单环境修复可从 16.2% 到 38.5%；作为 RL 环境时，结合 grounded verifier 和 dense per-step judge 的 reward 将 held-out score 从 58.8% 提升到 68.0%。
- 可迁移价值：非常适合启发可验证工具环境、自动 verifier、环境修复数据飞轮和 Agent RL sandbox。
- 局限：前 8 页能确认总体框架和核心结果，但具体 12 个环境的完整列表和失败分类需读后文。
- 证据来源：arXiv PDF 前 8 页。

### 3. OSReward: Instituting Standardized Evaluation for Cross-Platform Computer-Use Reward Models

- 方向：General Agent / Computer-use reward model / evaluation
- 核心方法：OSReward 把问题从“Agent 是否完成任务”转向“奖励模型/裁判是否可靠”。它构造跨 desktop、web、mobile 的 CUA 轨迹集，经过多阶段人工标注得到 ground-truth verdict，并进一步构造 OSReward-Hard 和 OSReward-Multi。论文还基于 OS-Shepherd-100K 训练 9B/35B reward model，目标是降低大规模评测和 RL 数据筛选中的裁判成本。
- 创新点：最重要的贡献是把 CUA 的 reward signal 本身变成标准化 benchmark。它指出许多 VLM judge 存在宽松偏差，容易把失败轨迹误判为成功，这对用轨迹做 RL 或数据蒸馏非常关键。
- 实验与 benchmark：前 8 页显示评测覆盖 27 个 VLM judge；OSReward-Hard 中平均 judge binary accuracy 下降到约 52%；数据集中成功/失败大致为 43%/57%，Hard 子集约为 30/70 success/fail，用来暴露 false success。
- 可迁移价值：适合用于设计 Agent RL 的 verifier/reward model 评估协议，尤其是“失败轨迹不能被廉价 judge 误标为成功”的问题。
- 局限：前 8 页对 OS-Shepherd 训练细节和 held-out transfer 结果只给概览，完整训练配方需要继续阅读。
- 证据来源：arXiv PDF 前 8 页。

### 4. TAPO: Transition-Aware Policy Optimization for LLM Agents

- 方向：General Agent / Agent RL / tool-use reasoning
- 核心方法：TAPO 针对 Agent RL 中只有稀疏终局奖励的问题，把 rollout 中天然存在的 `(state, action, next observation)` 转成 transition supervision。它在标准策略优化之外，交替加入 action-conditioned next-observation prediction，让模型学习动作会如何改变环境，而不是只学习哪条完整轨迹最后成功。
- 创新点：这是一种轻量、可插拔的 Agent RL 增强模块，不需要额外专家数据、额外采样或推理时开销。对真实工具使用很有启发：模型要稳定迁移，不只要知道“下一步做什么”，还要知道“做完以后环境会怎样反馈”。
- 实验与 benchmark：论文在 WebShop 和 ALFWorld 上评估，使用 Qwen2.5-1.5B-Instruct、Qwen2.5-7B-Instruct，并结合 GRPO/GiGPO。前 8 页显示 TAPO 在不同模型规模和 RL 算法上均提升成功率，例如 WebShop 上 7B + GRPO 从 66.1% 到 73.7%，ALFWorld 上也有 6.0% 和 2.8% 的成功率提升。
- 可迁移价值：适合引入到 tool-use、Search Agent、Code Agent 的环境反馈建模，尤其是把执行结果预测作为辅助训练目标。
- 局限：实验环境仍是 WebShop/ALFWorld 这类相对标准化环境，迁移到浏览器/代码仓库级长任务需要额外验证。
- 证据来源：arXiv PDF 前 8 页。

### 5. MANTA: Multi-Agent Network Topology Adaptation for Self-Evolving Multi-Agent Systems

- 方向：General Agent / Multi-Agent System
- 核心方法：MANTA 认为多智能体系统的问题不只是单个 Agent 能力，而是通信拓扑是否适合当前任务。系统在执行前基于经验初始化 task-conditioned topology，执行中监控协作轨迹，当组织方式不足时做有界结构更新，包括修改角色、通信边、执行顺序、信息可见性和验证路径。
- 创新点：把 inference-time self-improvement 从单个模型输出扩展到协作结构本身。它不是离线搜索一个固定拓扑，而是在任务执行过程中调整“谁和谁说话、谁验证谁、信息如何流动”。
- 实验与 benchmark：论文在五类 benchmark 上评估，覆盖 information seeking、tool use、planning、workflow execution 和 mathematical reasoning；MANTA 平均分 74.0，比最强 baseline 高 5.8 个百分点，并在 PlanCraft 上取得最佳结果。
- 可迁移价值：适合用于多 Agent Code/Search 系统，尤其是动态路由、专家角色、验证链路和信息可见性控制。
- 局限：前 8 页能确认总体机制和平均结果，但不同 benchmark 的具体失败模式和结构更新代价需读后文。
- 证据来源：arXiv PDF 前 8 页。

### 6. ClawTrack: Towards Trace-Level Evaluation and Improvement of Real-World Autonomous Agents

- 方向：General Agent / trajectory evaluation / data filtering
- 核心方法：ClawTrack 同时评估 Agent 做到了什么和怎么做到的。它引入 Task Score 与 Process Score，Process Grader 在每个推理回合上按目标一致性、效率、信息利用、结果验证四个维度评分，并用任务特定 rubric 约束。
- 创新点：它把 final answer success 拆成过程维度，可以过滤“撞对答案”的 lucky pass，也能定位失败来自规划、信息使用还是验证不足。论文还显示过程过滤后的轨迹可用于 post-training，提高不同规模模型表现。
- 实验与 benchmark：ClawTrack 包含 320 个任务、8 个领域、25+ deterministic mock services、12,541 个任务特定 rubric item；评估 21 个模型、16,000+ trials。前 8 页指出 result verification 是系统性瓶颈。
- 可迁移价值：非常适合 Code Agent 和 Search Agent 的训练数据清洗：不要只看最终通过/未通过，要记录每一步是否查证、是否使用了正确证据、是否验证输出。
- 局限：Process Grader 依赖 judge LLM，虽然论文声称对 evaluator choice 稳健，但具体成本和跨领域可靠性需要看完整实验。
- 证据来源：arXiv PDF 前 8 页。

### 7. Why Are GUI Agents Correct but Late? Decode on the Decision-Time Critical Path, Tested with Pre-Compiled Policy Trees

- 方向：General Agent / GUI Agent latency / runtime architecture
- 核心方法：论文指出 GUI Agent 有时不是不会做，而是 autoregressive decoding 太慢，正确动作生成时瞬时窗口已经关闭。AAPT 在空闲屏幕期间让同一个冻结多模态模型预编译 bounded conditional policy tree，包含可观察 guard、预授权动作和分支 deadline；事件发生后由轻量 observer 匹配屏幕变化并立即执行预备动作。
- 创新点：它把 GUI Agent 的瓶颈从模型能力转向 runtime latency，并提出“提前规划、事件时快速路由”的结构。这个思路适用于浏览器 Agent 中的弹窗、倒计时、动态页面和竞态交互。
- 实验与 benchmark：配对实验中，AAPT 在 contested decision window 内成功率从 0.50 提升到 0.79，McNemar 检验 p=1.8e-3，且未产生错误动作；独立多模态模型 126 次配对实验也复现效果，p=4.9e-13。
- 可迁移价值：对真实 Computer-use Agent 的执行系统很有价值，提示训练之外还要优化决策路径上的延迟和预授权动作。
- 局限：AAPT 更适合可预测短窗口事件，对开放式长任务的总体收益依赖事件类型分布。
- 证据来源：arXiv PDF 前 8 页。

### 8. SKILL-KD: Contrastive Skill Distillation for LLM Agents

- 方向：General Agent / skill distillation / agent memory
- 核心方法：SKILL-KD 把 skill 当成强弱 Agent 之间的显式蒸馏媒介。给定同一任务上的 student failure 和 teacher trajectory，它抽取二者的 actionable discrepancy，形成 textual skill patch；然后重新运行 student 验证 patch 是否有效，失败则继续 refine。为防止技能漂移，它维护 trace-linked edit history，并用 Drift-Aware Skill Consolidation 决定新增、删除、修改或跳过规则。
- 创新点：相比把成功轨迹总结成经验，SKILL-KD 更关注“学生失败和老师成功之间到底差哪条可执行规则”。这对长期维护 Agent skill library 很有启发。
- 实验与 benchmark：摘要和前 8 页说明论文在五个 Agent benchmark、两种 student 设置下评估，能持续提升冻结 student agent，相比 fixed-model adaptation baseline 更稳。
- 可迁移价值：适合做 Code Agent/Browser Agent 的失败归因式技能库：每条 skill patch 都应绑定失败轨迹、重跑验证和漂移控制。
- 局限：前 8 页未完整列出五个 benchmark 的全部名称和数值结果，需要读实验部分确认适用范围。
- 证据来源：arXiv PDF 前 8 页。

### 9. Contrastive Reinforced Policy Optimization via Privileged Self-Distillation

- 方向：Search Agent / Deep-search RL / agentic post-training
- 核心方法：CRPO 关注 OPSD 在多轮 agentic setting 中的 exposure bias。它用 predictive entropy 区分 positive positions 和 negative positions，把自蒸馏转成 group-wise contrast，以保留细粒度优化信号，同时避免推理路径收敛到错误方向。
- 创新点：对 Deep Search 最有价值的是，它把“强自教师给 dense guidance”中的副作用显式建模，并通过对比信号维持探索和稳定性。这比单纯 outcome reward 更适合长程检索和多步问答。
- 实验与 benchmark：前 8 页显示它在 13 个 reasoning 与 deep-search benchmark 上评估；Deep Search 包括 GAIA、WebWalkerQA、HLE、xbench，并启用 browser-equipped search engine。论文报告 CRPO 在 8B 规模上 GAIA-Avg. 有 +10.7% 提升，且在 Pass@1/3/5 下继续比较。
- 可迁移价值：适合 Search Agent 的 RL/post-training，尤其是多轮检索、反思、引用查证和浏览器工具链。
- 局限：前 8 页能看到 benchmark 和部分提升，但算法细节中的 entropy 阈值、负样本定义和训练稳定性还需完整阅读。
- 证据来源：arXiv PDF 前 8 页。

### 10. DataClawEval: A Benchmark for Data Engineering Agents in Real Industrial Harness

- 方向：Code Agent / Data engineering agent benchmark
- 核心方法：DataClawEval 构造真实工业数据工程 Agent benchmark。它从专业企业数据工程师写的生产级代码出发，生成 end-to-end 任务，要求 Agent 在隔离 Docker 环境中读取输入表、编写可执行代码、产出物化结果，再由任务特定 deterministic grader 判分。
- 创新点：它避免 Text-to-SQL 或简单数据分析题的静态答案评估，转向真实执行工件。评价不仅看输出表是否对，还看执行效率和工程质量。
- 实验与 benchmark：数据集含 100 个端到端任务，覆盖 PySpark、MySQL、HiveSQL、PrestoSQL/Trino、FlinkSQL 五类执行引擎；评估 16 个 frontier LLM-based data engineering agents，最强模型总体仅 74.9，且不同模型在不同引擎上各有专长。
- 可迁移价值：对 Code Agent 训练非常直接：任务构造、沙箱执行、case-specific grader、工程过程评分都可复用到仓库级修复和数据管道生成。
- 局限：领域偏数据工程，不覆盖通用软件仓库 issue resolution；但 benchmark 构造方法可迁移。
- 证据来源：arXiv PDF 前 8 页。

## General Agent

今日 General Agent 最强趋势是从“模型会不会推理”转到“系统是否能在真实环境中持续试错”。Qwen-UI-Agent、Echoverse、OSReward、MANTA、ClawTrack 和 AAPT 共同指向一个系统栈：可交互 runtime 提供真实状态变化，Agent 产生长轨迹，verifier/reward model 对轨迹可靠判分，过程评估定位失败，多 Agent 拓扑或 runtime 预编译机制再把失败转化为结构更新和训练信号。

建议优先精读 Qwen-UI-Agent、Echoverse、OSReward。三者分别覆盖基础 GUI Agent 系统、训练环境生成与修复、reward model 标准化，是最接近“真实工具使用后训练闭环”的组合。

## Search Agent

Search Agent 相关最值得关注的是 CRPO 和 MANTA。CRPO 明确包含 deep-search benchmark，并启用 browser-equipped search engine；它讨论如何在长程检索/推理中缓解自蒸馏的 exposure bias。MANTA 虽不是搜索专用，但五类 benchmark 中包含 information seeking，动态通信拓扑可迁移到多 Agent 检索系统：一个 Agent 负责 query planning，一个负责 evidence retrieval，一个负责 verification，拓扑根据任务难度和失败信号调整。

SciDataSailor 未进入 Top 10，但值得后续关注。它用 MCTS 合成科学数据探索轨迹，任务要求 Agent 浏览层级数据仓库、解释异构文件、执行分析并整合证据。该论文更偏科学数据场景，但“广度探索 + 目标利用 + 工具动作生成”的轨迹合成方法对 Search Agent 数据构造有迁移价值。

## Code Agent

Code Agent 今日最直接相关的是 DataClawEval、ClawTrack 和 SKILL-KD。DataClawEval 提供真实数据工程沙箱和 deterministic grader，适合参考其任务构造与工件级评分。ClawTrack 强调 trace-level process score，可用于仓库级 Agent 的失败归因，例如是否检查文件、是否运行测试、是否验证修复。SKILL-KD 则提供从失败轨迹和教师轨迹中蒸馏技能补丁的机制，适合构建可维护的 Code Agent skill memory。

Tycho 也值得作为候选继续读。它把 ARC-AGI-3 交互游戏建模为程序化 world model，由 coding-agent 构造、测试、修复可执行假设。虽然不是软件工程 benchmark，但“模型写出环境假设并用交互验证”的方式与自动调试、程序理解高度相似。

## 今日重点趋势

1. 真实工具使用能力越来越依赖 runtime 和数据飞轮，而不是单纯扩大模型。
2. Agent RL 的关键监督正在从终局 reward 转向 transition、process、judge reliability 和 skill patch。
3. Computer-use 评测开始暴露 false success、错误 FAIL verdict、轨迹证据缺失等基础测量问题。
4. 多 Agent 系统的优化对象开始从 prompt/role 文本扩展到通信拓扑、信息可见性和验证路径。
5. Code/Search Agent benchmark 正在向可执行环境、任务特定 grader 和轨迹级诊断靠拢。

## 潜在研究 idea

1. 为 Code Agent 构造 TAPO 式 transition supervision：从每次 shell/test/lint 输出中预测下一环境状态，并与修复策略共同训练。
2. 把 ClawTrack 的 process score 迁移到 Search Agent：对 query planning、网页证据选择、引用核验、答案合成分别打分。
3. 将 Echoverse 的 co-evolution loop 用于浏览器/代码沙箱：失败轨迹同时修复环境、补充 verifier、生成新的训练任务。
4. 为多 Agent Code Agent 引入 MANTA 式拓扑更新：当修复失败时动态增加 reviewer、tester、retriever 或 minimal-repro 角色。
5. 用 OSReward 思路专门评估 Code Agent reward model，测试它是否把未运行测试、假阳性修复、未验证输出误判为成功。

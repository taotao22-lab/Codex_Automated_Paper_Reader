## Code Agent

### 1. From C to Idiomatic Rust: A Ship-of-Theseus Agentic Translation

**问题背景**：论文关注成熟 C 系统迁移到 idiomatic Rust 的难点。直接让 LLM 把 C 翻译成 Rust 往往把语义恢复、所有权重构、生命周期推断、全局状态重写和 API 设计混在一次生成里，容易得到能编译但不安全、或看起来安全但行为不等价的代码。

**核心方法**：作者把迁移拆成两阶段：先用 c2rust 生成语义保持但不 idiomatic 的 Rust baseline，再用 agentic AI 按函数或小模块逐步替换成 idiomatic Rust。关键不是“模型一次写对”，而是维护一个持续可执行的混合代码库：每次改动后都通过编译和行为测试，再进入下一步。论文明确列出 C/Rust 差异维度，包括指针算术、void* 类型擦除、未初始化内存、malloc/free 资源管理、NULL 语义、C 字符串、static mut 全局状态等，并把这些差异转化为迁移任务。

**创新点**：这篇对 Code Agent 最大的价值在于把代码迁移定义为“可验证重构流程”而非“代码生成任务”。它提出了 dependency-aware ordering、FFI adapter scaffolding、static mut one-by-one wrapping、SAFE%/RUST% 度量等工程约束。对 agent 训练来说，这种任务天然包含计划、局部修改、运行测试、发现死锁或行为偏差、回滚/缩小改动粒度等闭环信号。

**实验与 benchmark**：论文在 iodine DNS tunnel 上评估，原项目约 12.5k SLOC C，最终得到 10,299 行 Rust，涉及 168 个函数签名迁移和 37 个 static mut 全局状态包装。PDF 报告初始 c2rust baseline 有 178 个 unsafe extern "C" fn、73 个 no_mangle、319 个 pointer arithmetic、144 个 deep unsafe memory operation；最终 SAFE% 达到 96%，RUST% 达到 57%。完整迁移约 37 developer-hours。这里的 benchmark 不是 SWE-bench 式问题集，而是一个真实系统迁移案例，评测重点是持续可编译、运行时行为验证和 unsafe surface 收敛。

**可迁移价值**：非常适合作为 Code Agent post-training 数据设计参考。可以把每个函数迁移、FFI wrapper 引入、static mut 包装、死锁定位、运行测试日志整理成多步轨迹，让模型学习“先保持系统可运行，再提高 idiomaticity”。这比单个函数翻译更接近真实 repo 级 agent 工作。

**局限**：论文案例是单项目，强依赖人工判断；作者也承认 migration unit 选择、变更排序和临时兼容层管理仍靠人工。PDF 里还保留 ACM 模板占位信息，正式发表质量需要谨慎判断。

**阅读建议**：精读第 3、4、6 节，尤其是 methodology、porting challenges、future work。把它加入 Code Agent / repository-level program repair / LLM-assisted migration 的 related work。

**证据来源**：arXiv PDF 前 8 页。

## General Agent

### 2. NeuroSynth: A Biologically Inspired Continual Reinforcement Learning Architecture for Mitigating Catastrophic Forgetting

**问题背景**：论文研究 continual RL 中灾难性遗忘：agent 在顺序学习新任务后，早期任务能力被新梯度覆盖。对 General Agent 训练而言，这对应长期任务、工具使用习惯和环境适应策略在持续更新中的稳定性问题。

**核心方法**：NeuroSynth 借鉴互补学习系统，把快速习得和慢速巩固拆成两个通路：plan pathway 负责较快适应当前任务，habit pathway 负责长期保留；再通过 replay 和 knowledge distillation 把稳定行为从快速通路迁移到长期通路。直观地说，它不是让一个策略网络同时承担“立即学会”和“长期不忘”，而是用结构分工减少参数更新互相覆盖。

**创新点**：对 Agent 方向的启发是把“任务记忆”做成可分层巩固的系统，而不是只靠 prompt 历史或普通 replay。它可以迁移到工具使用轨迹：新工具/新站点的快速探索进入短期通路，稳定操作模式通过蒸馏进入长期策略或检索记忆。

**实验与 benchmark**：论文使用 NeuroMaze-CL，一个自定义 continual reinforcement learning grid-world navigation 环境。3 个连续导航任务具有变化的目标位置，agent 接收 7x7 egocentric RGB 观测，episode 最长 150 步，和 PPO、EWC 比较，6 个随机种子。摘要报告最终 Task A 成功率 18.00% vs PPO 0.33%，Task B 35.33% vs PPO 0.00%；Task C 相对 EWC 为 9.00% vs 2.00%，但该差异不显著。

**可迁移价值**：可作为 agentic post-training 中“长期能力保持”的结构启发，尤其适合多环境 curriculum 或工具集合持续扩展。但它没有直接处理 LLM tool-use、浏览器或代码执行。

**局限**：环境较小，任务是导航而非真实工具使用；论文作者/场景显示实验成熟度有限，泛化到 LLM agent 需要重做环境和奖励设计。

**阅读建议**：略读，保留为 continual agent memory/replay 参考，不应作为日报主线。

**证据来源**：arXiv PDF 前 8 页。

## Search Agent

### 3. ParaASR: Multi-Token Prediction for Fast and Long-Context LLM-Based Speech Recognition

**问题背景**：LLM-based ASR 把语音识别转成“音频证据条件下的语言生成”，但大 decoder 的自回归生成带来延迟，长音频还要求跨片段一致性。

**核心方法**：ParaASR 在 4B LLM decoder 上加入 multi-token prediction branches，一次前向提出多个未来 token，再用自回归 verification 保证最终转写可靠。训练流程分阶段：先音频-语言预训练，再 ASR supervised fine-tuning，最后训练 MTP 分支。长音频数据还通过多系统验证 pipeline 生成 50K 小时长上下文伪标注，最后用 LLM 做全局重组和一致性修正。

**创新点**：它对 Search Agent 的间接启发是“proposal + verification”的解码结构。搜索 agent 也可以先并行提出多个查询/证据路径，再用可验证规则或引用一致性筛掉错误路径。它还说明长上下文监督可以通过多系统一致性生成，而不是完全人工标注。

**实验与 benchmark**：PDF 报告中文、英文和长形式 ASR benchmark 平均错误率分别为 2.97%、3.68%、3.70%，单 GPU serving RTF 低至 0.0053；WenetSpeech meeting 子集平均接受 5.0/6 个 proposed tokens。评测指标是 CER/WER/RTF，能力是语音识别准确率和推理延迟，不是信息检索。

**可迁移价值**：可迁移的是验证式并行生成和长上下文伪标注 pipeline，不是 ASR 任务本身。

**局限**：强依赖专有数据；任务远离 General/Search/Code Agent。

**阅读建议**：只看训练流程和 MTP verification 部分。

**证据来源**：arXiv PDF 前 8 页。

## 相邻系统与方法

### 4. DoubleHelix: Structured Cross-Modal Fusion for Audio-Visual Speech Recognition with LLMs

**问题背景**：传统 AVSR 往往一次性融合音频和视觉信息，面对噪声、遮挡或模态退化时缺少结构化的多轮纠偏。

**核心方法**：DoubleHelix 把融合改成迭代 cross-modal interaction。ReverseParallelHelix 做多轮音频/视觉交互并带 learned alignment constraints；QualitySensor 学习退化感知 gating；HelixReplication 在检测到退化时做一致性引导的条件增强。直观理解是，它让两个模态反复校正彼此，而不是把它们拼在一起后交给后端。

**创新点**：可迁移到多工具 agent 的地方是“质量传感器 + 条件增强”：当浏览器、检索、代码运行等某个工具信号质量下降时，系统应显式检测并触发备用证据或交叉验证，而不是统一拼接上下文。

**实验与 benchmark**：主要在 LRS3 上评估，训练还使用 VoxCeleb2 伪标签并形成 1,759 小时音视频训练数据。论文报告 clean audio WER 0.68%，相对 matched backbone 下前一最好结果提升 5.6%；babble noise SNR -5dB 下 WER 11.6%。benchmark 测的是音视频语音识别和噪声鲁棒性。

**可迁移价值**：适合作为多源证据融合设计参考，但不是 Search Agent 或 Code Agent 论文。

**局限**：领域特化强，指标和实验不覆盖工具调用、网页浏览或代码执行。

**阅读建议**：略读 QualitySensor 和 degradation-aware gating。

**证据来源**：arXiv PDF 前 8 页。

### 5. Linear Proposal Operators and Stochastic Search Geometry in SOMA and Differential Evolution

**问题背景**：论文分析 SOMA 和 Differential Evolution 这类随机优化算法，把候选生成、选择、替换和自适应混在完整流程里会掩盖 proposal operator 的几何结构。

**核心方法**：作者提出 operator-selection factorization，将 objective-independent variation operator 和 objective-dependent selection 分开分析。它用线性 proposal operators 描述 SOMA/DE 的候选生成，并研究 forced-coordinate binomial crossover 的随机几何性质；再把这些分析用于构造 operator-guided SOMA 变体。

**创新点**：对 agent 搜索的弱启发是：把“产生候选行动/查询”和“基于环境反馈选择候选”拆开建模。搜索 agent 的 query rewriting、网页跳转、工具调用候选也可以类似拆成 proposal rule 和 verifier/reward rule，便于做 RL 或离线轨迹分析。

**实验与 benchmark**：论文使用 exact enumeration 和 Monte Carlo 验证解析结论，并在完整 noiseless BBOB benchmark 上评估 operator-guided SOMA 变体，覆盖三个维度和两个 evaluation budgets。BBOB 测的是连续黑盒优化性能，不是网页搜索。

**可迁移价值**：可作为“搜索轨迹几何”和候选生成/选择分解的理论类参考。

**局限**：不是信息检索，也没有 LLM、工具调用或自然语言任务。

**阅读建议**：只读 operator-selection factorization 的动机。

**证据来源**：arXiv PDF 前 8 页。

### 6. Analysis of Memory-Runtime Trade-offs in Caching Strategies for Genetic Programming Symbolic Regression

**问题背景**：GPSR 会反复评估完整表达式或子表达式，fitness evaluation 成为主要运行时瓶颈。对 agent 系统的弱相关点是：长程搜索中大量候选状态/子任务会重复计算，需要缓存策略。

**核心方法**：论文比较多种 caching mechanisms，研究 cache size、replacement policy、proactive cleaning 对运行时间和内存的影响，并用无限大 cache 的 key-value 访问频率分析指导容量设置。

**创新点**：它不是 agent paper，但“子表达式缓存”可迁移到代码 agent 的测试结果缓存、搜索 agent 的网页证据缓存、tool-use trajectory 的中间观察缓存。更重要的是，它提醒缓存策略不能只看命中率，还要看 memory-runtime trade-off。

**实验与 benchmark**：使用 PMLB 的 344_mv、215_2dplanes、1203_BNG_pwLinear 三个数据集；每个数据集 0 到 7 随机种子，75:25 划分，训练 500 epochs；运行时在 Google Cloud c3-highcpu-22 上测量。论文报告合适缓存可把 fitness evaluation 时间降低一个数量级或更多。

**可迁移价值**：适合作为 agent runtime 的缓存策略旁证，不适合作为核心 related work。

**局限**：任务是符号回归，不涉及 LLM 规划、工具调用或真实环境反馈。

**阅读建议**：略读结论和 caching guideline。

**证据来源**：arXiv PDF 前 8 页。

## 潜在研究 idea

1. 构造 C-to-Rust / unsafe-to-safe Rust 的 agentic migration benchmark：每个样本包含 c2rust baseline、小步迁移目标、编译日志、单元/集成测试和最终 unsafe surface 变化。
2. 把 Code Agent 训练轨迹拆成 proposal 与 verifier：模型先提出多个局部修改方案，再由编译、测试、静态分析和运行日志选择可接受方案。
3. 为 long-horizon tool-use agent 设计分层记忆：短期探索轨迹保留在快速通路，稳定工具模式通过蒸馏进入长期策略。
4. 在 Search Agent 里加入 evidence quality sensor：当来源冲突、网页不可访问或引用链薄弱时，触发补充检索和交叉验证。
